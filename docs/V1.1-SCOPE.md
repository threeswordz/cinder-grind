## 1. Objective

Turn the delivered V0.1–V1.0 *module-first* ERP into a **role-first, operational UI** reusing canonical business records and backend state machines. It is a modular incremental React/MUI UX redesign, **not** a backend rewrite, new accounting product or implicit authorization for all 54 Phase 2 business items.

The user-reviewed English mockup defines a **living visual direction** only; illustrations are not verified data or approved functional actions. Subsequent layout/menu/form improvements are allowed under the relevant approved stage and standard CI/PR rules. All business behavior changes require explicit Change Control.

## 2. Approved in scope — bounded V1.1 release

- One identity per login. Administrator-assigned `roleCodes` and *effective* `permissions` determine allowed navigation, source tasks and actions automatically. **No Switch Role, impersonation, View-As, password sharing or user-selectable role elevation.**
- Responsive grouped sidebar, header, Home, My Work, breadcrumbs, safe source links, Project context from existing authorized project APIs, UI chrome in English, Thai and Traditional Chinese. Company context must not pretend multi-company switching exists when session is company-bound.
- Eight source PDF operating personas (Nancy Accounting Manager, Ben General Manager, Khaimook Project Manager/Head of Store, Jai Purchasing Staff, Store Site Store Staff, Foreman Site Foreman, Porn Accounting Staff, Koh HR Staff) as examples to **configure through existing roles/permissions**, never hard-coded per-name authority or invented staff.
- Authenticated **source-derived** task/approval views only. Scoping uses existing Company, active Employee/Project Member, record permission and configured approval-step rules. No cross-project counts, custom mutable to-do ledger or second approval engine.
- Reuse existing Project/WBS/Scheduling, BOQ, PR/RFQ/Quotations/PO, Inventory, Subcontracts/Claims/Certifications, Finance AP/AR/Payments/Retention and Cost Control/Management views in connected UX journeys.
- First vertical slice: **purchasing**, followed by receiving, subcontract, finance and project/control. Source-owned API actions only, zero fictional transitions. Store Site creates PR, Khaimook PR approval, Jai RFQ/PO preparation, Ben PO approval per actual configuration. Store Site delivery evidence; any Jai GR confirmation rule is still approval-gated.
- Small reusable source-adapter/route components; preserve existing domain workspaces until their replacements are tested and accepted.
- Accessible desktop/tablet/mobile UI and honest error/loading/empty states; source-backed THB only for THB records, without FX or changed persisted decimals/IDs.
- Documentation, 54-item traceability and approved rules/non-regression evidence updated with each authorized stage. V1.0 history preserved.
