# V0.7 Cost Control — Scope Baseline

**Status:** APPROVED BY PRODUCT / BUSINESS OWNER — 2026-10-03  
**Entry Gate Issue:** #137  
**Implementation:** ACTIVE — V0.7-A through V0.7-D technically complete; V0.7-E Cost Reporting / Hardening / Release Evidence active

## 1. Purpose

V0.7 integrates approved Budget, Procurement, Subcontracts and Finance source records into project Cost Control without creating a second editable source of truth.

The critical rule is permanent for this release:

**Committed Cost, Actual Cost and Paid Cost are separate measures.**

## 2. Must Have scope

1. Consume immutable Original Budget from the first approved V0.3 Budget Revision.
2. Consume current Revised Budget from the highest/current approved V0.3 Budget Revision.
3. Derive Procurement and Subcontract Committed Cost without double counting revision history or Work Order allocation.
4. Derive Actual Cost from the approved COST-014 / D06-08 sources.
5. Derive Paid Cost from approved Finance settlement evidence under D07-02, separately from Project Cash Flow.
6. Add controlled Direct Cost Posting for costs not already represented by AP/Subcontracts.
7. Add versioned Cost Forecast / uncommitted ETC.
8. Derive Remaining Commitment, Cost to Complete, Forecast Cost and Variance.
9. Add client/project commercial Variations distinct from V0.5 subcontract Variations.
10. Expose Original Contract Value, Revised Contract Value, Actual Revenue, Cash Received and Forecast Revenue as separate measures.
11. Derive Forecast Profit and Actual Profit from approved measure definitions.
12. Support Project / WBS / Cost Code rollups, including explicit Unallocated values where canonical allocation is absent.
13. Provide integrated Cost Control reporting and authorized source traceability.
14. Preserve Company isolation, effective Project access and explicit Cost Control permission boundaries.
15. Retain audit/history, Decimal financial authority, concurrency/idempotency protection and full regression/live HTTP evidence.
16. Prepare mandatory Product / Business Owner V0.7 human UAT and explicit release acceptance at release exit.

## 3. Source-module ownership

- **V0.3 BOQ/Budget:** owns BOQ, Budget Revisions, Original Budget and Revised Budget.
- **V0.3 Procurement:** owns Purchase Orders and approved PO revision history.
- **V0.4 Inventory:** owns quantity-based Goods Receipt / Stock Transactions / Material Issue / Return / Transfer. Inventory valuation is not introduced in V0.7.
- **V0.5 Subcontracts:** owns Agreements, Work Orders, Claims, Assessments, Certifications, retention evidence and subcontract Variations.
- **V0.6 Finance:** owns Supplier Invoices, Client Invoices, Payments, allocations, AP/AR and Project Cash Flow.
- **V0.7 Cost Control:** owns only Direct Cost Postings, versioned Cost Forecasts/lines and client/project Variations.

Cost Control may derive read models from source modules but must not copy those source transactions into another editable ledger.

## 4. Explicit exclusions / deferrals

Unless separately approved through Change Control, V0.7 excludes:

- tax/VAT and statutory accounting;
- GL/journals;
- FX/multi-currency conversion or mixed-currency aggregation;
- Inventory valuation and Material Issue cost recognition;
- supplier matching tolerances/automation;
- retention release/payment workflow;
- detailed client progress-billing;
- synthetic/proportional allocation of ambiguous cost/payment/certification values;
- invented WBS/Cost Code revenue allocation where canonical source allocation does not exist;
- advanced historical trend/snapshot analytics beyond approved Forecast versions;
- V0.8 cross-project management dashboards;
- advanced report/export scope owned by RPT-011 unless separately brought forward;
- automated EQP-009 Equipment Cost Allocation until a canonical equipment rate/valuation rule is approved.

Manual equipment-related expense may still be represented by an authorized Direct Cost Posting when it satisfies D07-07.
