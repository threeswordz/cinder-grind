## Scope implemented

Stage C implements the approved Forecast / ETC / Variance portion of COST-006/007/008/013 and RPT-009 under DEC-024, D07-01/03/06/08/09/10, BR-V07-01/03/07/11/13–16 and applicable AC-V07-013–015/020–024/026–043/047–050.

- V0.7-owned versioned Cost Forecast headers and lines.
- Persisted Forecast input is **Uncommitted ETC** only.
- Current Forecast is derived from the highest-version final-approved Forecast; rejected/draft higher versions never supersede it and there is no editable `is_current` flag.
- Remaining Procurement Commitment is current applicable PO-line commitment less only canonically PO-linked approved Supplier Invoice Actual, floored at zero.
- Remaining Subcontract Commitment is current approved Agreement ceiling less approved non-reversed Certification gross Actual, floored at zero.
- Subcontract remaining balance stays explicit **Unallocated** where Certification has no approved lower-dimensional allocation; no Work Order/synthetic proration is invented.
- Cost to Complete = Remaining Commitment + Uncommitted ETC.
- Forecast Cost = Actual Cost + Cost to Complete.
- Variance = Revised Budget − Forecast Cost.
- Project/WBS/Cost Code filtering and parent-WBS descendant behavior reuse the integrated Cost Control read model.
- PostgreSQL/Prisma Decimal and exact server-side aggregation remain authoritative.

## Persistence / lifecycle integrity

Forward-only migrations:
- `20261003160000_v0_7_c_cost_forecast`
- `20261003161500_v0_7_c_forecast_permissions`
- `20261003174000_v0_7_c_forecast_line_parent_immutability`

Forecast persistence includes deterministic Project-scoped version numbering, lifecycle/approval evidence, immutable approved/rejected history, idempotency/replay evidence and canonical Forecast lines.

- New Forecast versions serialize through the Project boundary before assigning the next version number.
- Drafts are maker-editable only; submitted/terminal source fields are protected.
- Approval actions serialize on the Approval Instance, receive database-authoritative decision order/time and require current-step Approval Matrix authority.
- Maker-checker, explicit `cost.forecast.approve`, active step-role authority and effective Project scope are all required.
- Terminal actor/time/rejection evidence binds to retained serialized approval actions.
- Approved/rejected Forecast history cannot be silently edited or deleted.
- New Forecasts require an active Project and current Company base currency; unsupported FX behavior is not introduced.

## Security / visibility

- `cost.forecast.view`, `cost.forecast.manage`, and `cost.forecast.approve` are explicitly seeded under COST_CONTROL.
- No Forecast permission is implicitly granted to SYS_ADMIN.
- Effective database-derived Project access remains independent of Cost Control permission.
- `projects.access_all` broadens Project visibility only and grants no Forecast business approval.
- Aggregate Cost Control may expose authorized totals without exposing protected source records.
- Mixed Remaining Commitment evidence is always sanitized at aggregate scope.
- Procurement remaining-detail evidence additionally requires Procurement PO + Finance Supplier Invoice source permissions.
- Subcontract remaining-detail evidence additionally requires Agreement + Certification source permissions.
- Forecast source records require explicit Forecast source permission.
- Archived Projects remain selectable when retained Direct Cost **or Forecast** history exists; new Forecast creation remains active-Project-only.
