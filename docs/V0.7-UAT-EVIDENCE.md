## Human walkthrough

Use an approved UAT Company/Project and business-role accounts. A technical SYS_ADMIN account must not substitute for a Cost Control business approver.

### 1. Integrated cost position and source ownership

1. Open Cost Control for an authorized Project.
2. Reconcile Original Budget and Revised Budget to the approved Budget source.
3. Reconcile Procurement and Subcontract commitments to their canonical source records.
4. Reconcile Supplier, Subcontract and Direct Actual Cost.
5. Reconcile Paid Cost to eligible approved Finance settlement evidence.
6. Verify Committed, Actual and Paid remain visibly separate.

**Expected:** Cost Control consumes source-owned values and does not create a second editable cost ledger.

### 2. Project / WBS / Cost Code reporting

1. Open the RPT-009 Cost Report for the UAT Project.
2. Review the Project-level totals.
3. Filter to a parent WBS and verify eligible descendants are included without double counting.
4. Filter by Cost Code.
5. Verify missing WBS/Cost Code attribution is shown explicitly as Unallocated rather than silently dropped or proportioned.
6. Verify Budget, Committed, Actual, Paid, Forecast, Cost to Complete and Variance are shown as distinct measures.

**Expected:** AC-V07-021–024 pass and no synthetic dimensional proration is introduced.

### 3. Forecast / ETC / variance

1. Create a Forecast Draft containing Uncommitted ETC lines.
2. Submit through the configured workflow.
3. Verify maker-checker separation and approve as the configured checker.
4. Confirm the highest approved version becomes the current Forecast.
5. Reconcile Remaining Commitment, Cost to Complete, Forecast Cost and Variance.
6. Create/reject a higher Forecast version and verify it does not supersede the approved current version.

**Expected:** Forecast calculations follow D07-03 and approved history remains immutable.

### 4. Direct Cost Posting

1. Create a Direct Cost Draft against valid Project / Cost Code and optional WBS.
2. Submit and approve through the configured workflow.
3. Verify it contributes Actual Cost but does not automatically become Paid Cost.
4. Create a linked reversal and verify the exact signed offset preserves history and dimensions.
5. Verify the maker cannot approve the maker's own posting.

**Expected:** D07-07 and maker-checker/integrity rules hold.

### 5. Project Variations / contract / revenue / profit

1. Create a positive Project Variation, submit and approve it.
2. Verify Revised Contract Value and Forecast Revenue increase by the approved delta.
3. Verify Actual Revenue and Cash Received do not change solely because a Variation was approved.
4. Create and approve a linked compensating reversal; verify the commercial effect is neutralized while history remains.
5. Repeat with a negative Variation.
6. Reconcile Actual Profit = Actual Revenue − Actual Cost.
7. Reconcile Forecast Profit = Forecast Revenue − Forecast Cost.

**Expected:** D07-04/05 apply exactly and revenue/profit remain Project-level where no approved lower-dimensional allocation exists.

### 6. Source traceability / permission sanitation

1. Use a user with `cost.control.view` but without detailed Finance/Subcontract source permissions.
2. Open Cost Control and the RPT-009 report.
3. Verify aggregate measures remain visible.
4. Verify protected source identifiers/details are sanitized.
5. Add the appropriate source-module view permission and verify authorized detail becomes available.

**Expected:** D07-10 and AC-V07-033 pass without aggregate leakage.

### 7. Project access / technical administration boundary

1. Use a user with `cost.control.view` but no effective access to another Project.
2. Verify direct Cost Control access to that Project is denied.
3. Verify report selectors do not expose inaccessible Projects.
4. Verify `projects.access_all` alone does not grant Cost Control permission.
5. Verify technical SYS_ADMIN alone does not grant Direct Cost / Forecast / Project Variation business approval authority.

**Expected:** AC-V07-026–032 pass.

### 8. Currency / precision / integrity

1. Review a base-currency Project with high-precision Decimal source values.
2. Verify displayed/report totals reconcile to server/database values.
3. Use or simulate an unsupported non-base-currency eligible source.
4. Verify Cost Control fails closed rather than reinterpreting or converting it.
5. Verify approved Direct Cost / Forecast / Project Variation history cannot be silently edited/deleted.

**Expected:** AC-V07-034–041 pass.

### 9. Approved exclusions

Confirm V0.7 has **not** introduced:

- synthetic WBS/Cost Code revenue/profit allocation;
- advanced historical trend/snapshot analytics;
- V0.8 cross-project management dashboards;
- RPT-011 advanced export/report functionality;
- automated EQP-009 Equipment Cost Allocation;
- tax/VAT;
- FX conversion;
- GL/journals;
- duplicate editable Budget/Committed/Actual/Paid/Revenue totals.
