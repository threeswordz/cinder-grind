## 2. Should-Have delivery / deferral

The ten V0.2 Should-Have requirements are explicitly accounted for:

- PRJ-008 Project Actual Dates — delivered.
- SCH-003 Summary Activities — delivered.
- SCH-009 Dependency Lag — delivered.
- SITE-004 Material Usage Recording — delivered as observational Site data; no Inventory posting.
- SITE-006 Weather Recording — delivered as local observation; no external weather dependency.
- SITE-009 Inspection Recording — delivered as lightweight references/remarks; no full QA/QC workflow.
- EQP-002 Equipment Type — delivered.
- EQP-005 Equipment Availability — delivered as a derived read model.
- DOC-010 Document Categories — delivered through Document Types.
- ADM-008 Project and Activity Types — Activity Types delivered; Project Type configuration is the documented deferred remainder.

The deferred Project Type remainder does not change the canonical Project/WBS/Activity model and does not block a V0.2 Must-Have acceptance flow.

## 3. Ground Floor Slab independent reference

The reusable reference dataset fixes the expected result before execution:

- WBS: Groundworks → Ground Floor Slab.
- Detailed Activities: Setting Out, Excavation, Compaction, Blinding Concrete, Formwork, Reinforcement, Inspection, Concrete Pour.
- detailed durations total exactly 20 working days.
- Monday–Friday reference calendar.
- planned window: 2026-10-01 through 2026-10-28.
- controlled one-working-day forecast shift: 2026-10-02 through 2026-10-29.
- sequential Finish-to-Start detailed chain.
- all detailed Activities on the reference critical chain have zero Total Float.
- baseline remains at planned dates while forecast, actual and progress may change.
- Gantt/read-model forecast dates, Critical Path and Total Float must exactly agree with backend Scheduling Engine results.
- 2-week and 4-week lookahead membership is asserted independently.

## 4. Cross-cutting evidence

The Validate Construction ERP workflow starts from an empty PostgreSQL service and verifies:

- frozen dependency installation
- Prisma Client generation and schema validation
- all source-controlled migrations
- migration status
- production dependency audit
- API and web TypeScript checks
- unit and PostgreSQL integration tests
- V0.1 regression
- V0.2-A/B/C/D/E/F regression
- V0.2-G Groundworks reference acceptance
- live HTTP acceptance
- production builds

Project-scope denial is explicitly exercised for Scheduling, Documents, Site Execution, Equipment and Reporting.

## 5. Human acceptance boundary

Automated evidence proves technical/business-rule behavior that can be asserted deterministically. It does not self-approve:

- supported-device visual/usability acceptance
- business fitness judgment
- Product / Business Owner release acceptance

Those remain recorded in `docs/V0.2-UAT.md`.
