## Objective

Establish the reusable backend Management read-model and KPI-contract foundation without creating a second editable source of truth.

## In scope

- Management permission catalogue: `management.dashboard.view`, `management.portfolio.view`, `management.report.export`.
- Project-scoped Management summary contract.
- Authorization-safe portfolio foundation.
- Composition of canonical Scheduling/Site, Procurement, Inventory, V0.7 Cost Control and V0.6 Cash Flow summaries.
- Explicit available/unavailable states and aggregate source-traceability metadata.
- Company/Project authorization negatives, SYS_ADMIN separation and projects.access_all separation.
- Decimal/base-currency-safe financial output.
- Regression and authenticated live acceptance.

## Boundaries

Management is read-only composition. Stage A does not mutate source modules, create an editable KPI ledger, create a second schedule/risk/cost/finance engine, expose protected source rows through Management permission, synthesize dimensions, or implement V0.8-B–E UI/export scope.

## API foundation

- `GET /management/projects/:projectId/summary`
- `GET /management/portfolio`

## Security

Project summary requires `management.dashboard.view` plus effective Project access. Portfolio requires `management.portfolio.view`; inaccessible Projects are excluded before aggregation. `projects.access_all` and SYS_ADMIN do not imply Management permission. Protected source detail remains source-permission gated.

## Data / performance

No canonical V0.8 operational/financial table is required for Stage A. Permission additions use a forward-only migration. Financial values remain server/database Decimal-derived and base-currency-only. Portfolio authorization filtering occurs before aggregation and must avoid per-row authorization queries.
