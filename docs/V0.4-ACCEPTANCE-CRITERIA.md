# Construction ERP — V0.4 Inventory Acceptance Criteria

**Status:** APPROVED — Product / Business Owner approval recorded 2026-09-27  
**Scope source:** `docs/V0.4-SCOPE.md`  
**Business-rule source:** `docs/V0.4-BUSINESS-RULES.md`

## Warehouse and authorization

- **AC-V04-001:** An authorized user can create and maintain a Company-scoped Warehouse with a unique code, active state, location and optional Project/Site context.
- **AC-V04-002:** A Warehouse with transaction history cannot be deleted or reassigned across Company/Project scope; it can be archived subject to approved rules.
- **AC-V04-003:** Company and Project scope plus explicit Inventory permissions are enforced server-side for reads, workflow actions, posting, reversal, reports and document targets.
- **AC-V04-004:** An unauthorized or unassigned Project user cannot discover or act on protected Inventory records through direct API calls.

## Goods Receipt

- **AC-V04-005:** An authorized user can create a Draft Goods Receipt against eligible material lines from an active approved Purchase Order revision.
- **AC-V04-006:** one PO line can be received through multiple posted Goods Receipts and cumulative received quantity is derived across the stable PO/revision lineage.
- **AC-V04-007:** partial receipts are allowed; a post exceeding the approved cumulative quantity is rejected under the approved zero-tolerance rule.
- **AC-V04-008:** Goods Receipt material, UOM, Supplier, Company, Project and PO source references are validated and retained.
- **AC-V04-009:** posting a Goods Receipt atomically creates immutable positive Stock Transactions and changes the derived balance exactly once.
- **AC-V04-010:** retrying the same posting request cannot create a duplicate physical-stock effect.
- **AC-V04-011:** posted receipt correction uses an auditable reversal/new document path; posted source history cannot be edited or deleted.

## Ledger, balance and Project/Site stock

- **AC-V04-012:** every physical receipt, issue, return, transfer and reversal has immutable ledger entries linked to its source document and actor/time evidence.
- **AC-V04-013:** Stock Balance is calculated from posted Stock Transactions by Company, Warehouse, Material and Project attribution; it is never manually edited.
- **AC-V04-014:** concurrent posting is serialized sufficiently to prevent duplicate effects, over-receipt and negative stock.
- **AC-V04-015:** Project/Site stock can be filtered and reported without bypassing Project authorization.

## Reservation, issue and return

- **AC-V04-016:** an authorized user can reserve available stock against valid Project and optional WBS/Activity context without changing physical on-hand quantity.
- **AC-V04-017:** available stock equals on-hand stock less active reservation quantity for the same controlled dimensions.
- **AC-V04-018:** posting a Material Issue atomically reduces stock and rejects insufficient available/on-hand stock under the approved reservation rules.
- **AC-V04-019:** a Material Return references a prior posted Issue and cannot exceed the remaining returnable quantity.
- **AC-V04-020:** posting a Return atomically increases stock while preserving Issue/Project/allocation traceability.
- **AC-V04-021:** reservation release and fulfillment retain history and never rewrite physical Stock Transactions.

## Transfer

- **AC-V04-022:** a posted Stock Transfer atomically creates a matched source decrease and destination increase for the same Material, quantity and UOM.
- **AC-V04-023:** transfer posting rejects identical source/destination Warehouses, insufficient source stock, invalid scope or unsupported inter-company movement.
- **AC-V04-024:** transfer reversal is atomic, auditable and cannot produce duplicate effects.

## Documents, reporting and release quality

- **AC-V04-025:** Inventory transaction documents reuse the secure Documents abstraction with validated same-Company/same-Project target integrity.
- **AC-V04-026:** authorized users can report derived balances and movement history by relevant Company, Project, Warehouse, Material, transaction type, source and date filters.
- **AC-V04-027:** Inventory reports expose source traceability without introducing a second ledger or editable reporting store.
- **AC-V04-028:** all Stock-changing actions create audit evidence and preserve maker-checker separation where approval is required.
- **AC-V04-029:** no Inventory transaction creates Finance, Actual Cost or accounting postings in V0.4.
- **AC-V04-030:** migration-from-zero, full regression, Inventory integration/concurrency/authorization tests, live HTTP acceptance, production builds and dependency audit pass on the exact release head.
- **AC-V04-031:** Product / Business Owner completes the V0.4 business walkthrough, accepts any documented non-blocking workaround and explicitly approves the release before V0.4 is closed.
