## 5. Known test-harness limitation

Running the complete `deploy/uat/prepare-release.sh` regression repeatedly against a populated, persistent UAT database can collide with retained integration-test fixtures and concurrent test transactions. The observed failures were duplicate-fixture and deadlock/serialization conflicts rather than failed V0.3 business assertions.

The approved operational approach is to run the full release regression against a clean isolated test database and use `deploy/uat/runtime-acceptance.sh` for the populated UAT runtime. Clean CI and the populated-environment runtime acceptance are green. This limitation is a non-blocking tooling follow-up and does not change V0.3 production behavior or the accepted business result.
