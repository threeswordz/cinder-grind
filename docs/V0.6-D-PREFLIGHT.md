## 3. Functional boundary

### 3.1 Subcontract Finance Payment reference

- V0.5 Subcontract Certification remains the Subcontracts-owned certification record.
- Finance remains the sole owner of Payment and allocation records.
- Authorized Subcontract views may display linked Finance Payment number/status/reference and relevant settlement state read-only.
- The Subcontracts module must not create, edit, approve, cancel or duplicate Finance Payment data.
- Visibility must respect Company and effective Project access plus the underlying Subcontract/Finance read permissions.

### 3.2 Payable retention visibility

- Retention withholding is derived/recorded from approved V0.5 Certification retention evidence.
- The Stage-D view exposes source Certification, Agreement/Project context, original withheld amount, active balance/effect and reversal/correction traceability.
- D06-15 base-currency compatibility applies before Finance retention accounting is created/derived.
- D06-16 allows a system-generated compensating retention-withholding correction only when a Certification reversal legally proceeds after active Payment allocations are cleared.
- Original source/correction history remains traceable and ordinary application flows must not hard-delete it.

### 3.3 Retention ledger boundary

If `retention_ledger_entries` is materialized, it is the approved Finance retention ledger from the V0.6 data-model baseline and must:

- remain source-linked to the Subcontract Certification;
- represent withholding/balance and D06-16 compensating reversal evidence only;
- use Company base currency;
- preserve immutable historical entries;
- prevent duplicate effects through source identity / idempotent constraints;
- never become a retention release/payment authorization ledger.

A fully derived read model is acceptable where it satisfies the approved data/API boundary without creating duplicate mutable truth. Implementation must choose the smallest canonical model consistent with existing baselines.

### 3.4 DOC-009

Extend the existing Documents owner/storage/link abstraction only for these approved targets:

1. Supplier Invoice
2. Client Invoice
3. Payment
4. Subcontract Agreement
5. Subcontract Work Order
6. Subcontract Claim
7. Subcontract Certification
8. Subcontract Variation

Rules:

- no second file store or Finance/Subcontract-specific binary storage;
- file bytes remain outside PostgreSQL under the existing storage provider;
- existing `documents.document.view/upload/link/archive` permissions remain authoritative;
- target Company/Project authorization must be revalidated server-side;
- archived/historical documents remain retained rather than physically deleted by ordinary flows;
- target expansion beyond the eight approved entities requires Change Control.

## 4. Authorization baseline

Stage D must preserve:

- `finance.retention.view` for Finance retention visibility;
- applicable Subcontract read permissions for Subcontract-side payment-reference presentation;
- existing Documents permissions for document actions;
- `projects.access_all` only bypasses Project assignment and grants no Finance/Subcontract/document mutation authority;
- technical SYS_ADMIN does not imply Finance or Subcontract business authority;
- Company isolation is mandatory;
- Project-scoped reads/actions require effective Project access.

The backend remains the security boundary even when frontend controls are bypassed.

## 5. Data / integrity baseline

- UUID internal identity and existing Company/Project ownership patterns.
- DECIMAL authority for money; no JavaScript floating-point authority.
- Company base currency only; no FX conversion.
- forward-only migrations only; never modify executed migrations.
- Subcontract Certification remains the source of retention-withholding evidence.
- Finance Payment remains the source of settlement evidence.
- documents remain canonical Documents records/links rather than copied module attachments.
- any compensating retention correction retains the original source link and may not erase or overwrite the original withholding evidence.
- cost-state separation remains: retention accounting/payment references do not create V0.7 Actual/Paid/Committed Cost ledgers.
