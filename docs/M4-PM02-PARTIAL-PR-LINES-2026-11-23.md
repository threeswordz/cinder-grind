## Source behavior staged — bounded native actor and RFQ proof PASSED (NOT full UAT)
- POST /api/v1/procurement/purchase-requests/:requestId/decide-lines requires live auth, CSRF, existing procurement.pr.approve capability, PROJECT_MANAGER, original-maker denial, configured ApprovalService step and Project scope.
- Requires one configured single-reviewer workflow step, the exact approval-instance UUID and an exhaustive set of submitted line UUIDs with APPROVED or RETURNED; every RETURNED line has a reason. Multi-step workflows fail closed rather than inventing reviewer consensus. Generic prior whole-PR approve/reject remains intact; once any PM02 line decision is selected, the UI disables legacy whole-PR approval and the mutation independently refuses to discard the selection.
- ApprovalService and all line dispositions are in one Serializable transaction. All decisions and reasons persist and are independently audited. Returned lines are excluded from approved demand, RFQ creation, supplier award and Purchase Order available awards/create/approve/revise. Legacy NULL reviewDecision with an APPROVED parent remains fully eligible without rewriting historical rows.
- Original PR maker only uses copy-returned to make a new Draft containing only returned lines (stable source-line UUID pointer, corrected quantity/description etc. editable through existing Draft routes), retains immutable prior approval/return. Rejected linked correction requests also copy as a single-successor chain of linked lines with original-maker-only rights, rather than being flattened to unrestricted drafts. Ordinary rejected non-correction PRs retain existing copy behavior. Unique source correction prevents double reissue; a returned-again correction can be copied in its own next cycle. **Cancellation of a linked correction draft, deletion of its source-linked lines and adding unrelated lines to it are denied** until a governed replacement mechanism exists, avoiding permanently stranded returned demand.
- A separate forward-only PM02 trigger migration permits **only** transaction-local final review metadata after a recorded approval action (native PostgreSQL 17.11 migration and PM02 actor test passed at source `7c56b949b1a509f47fbefb237c9bfabd8b48f164`); every submitted PR business field remains frozen. The existing copy-source trigger now admits the original maker's approved-with-returned-line source, in addition to ordinary rejected sources.
- No new permission code or automatic retained role grant. Existing approved PRs, RFQs, POs and historical stock/Finance state are unchanged. SQL migration only adds nullable columns, a SQL-three-valued-logic-safe consistency CHECK (`IS TRUE`) and unique correction lineage.
