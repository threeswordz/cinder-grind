## Codex stable-candidate review remediation

First stable-candidate review on `a288dff64f1068840762eaf1ec8aeb88b4836727` found three genuine issues:

- **P1:** Nest log buffering would prevent structured runtime logs from reaching stdout/stderr. Remediation removes `bufferLogs: true` so default Nest logging is emitted immediately.
- **P1:** the benchmark used session-only read/mutation paths. Remediation moved the evidence to an authenticated Project-list read plus a real Project mutation path; later review rounds further hardened timing and state safety.
- **P2:** the stock regression guard pointed at Warehouse CRUD. Remediation binds AC-V10-033 stock evidence to `procurement/purchase-order.integration.spec.ts`, which contains the actual competing stock-transfer / receipt-reversal regressions.

All three were present on remediation head `8729de04ccebe82c2a3ad12a4872f588e68a54f2`; push CI #4019 and PR CI #4020 both PASS.

The material re-review on `2e35ea615b84789ca35d4186c3b31a9b4005665e` identified two additional genuine issues:

- **P1:** storage readiness checked permissions/sentinel but did not prove a real write was possible under ENOSPC/EDQUOT conditions. Remediation adds a bounded UUID-named create/delete probe inside the configured storage root, with best-effort cleanup on failure.
- **P2:** benchmark latency stopped when response headers arrived. Remediation consumes the complete response body before stopping each latency sample.

Those fixes remained green through head `915bf5805575bcb870b4ecb61807fe15d21e19cd`, where the next review identified two further P2s:

- **P2:** Production rollback deletion called the write-capacity probe before unlink, so a full filesystem could prevent cleanup. Remediation separates Production storage identity/sentinel validation from the readiness write probe and regression-covers ENOSPC-style rollback removal.
- **P2:** an ambiguous Project PATCH response could skip deterministic restoration. An initial unconditional restore/verify remediation was added, then superseded by the stronger state-idempotent mutation design below.

Final exact-head review on `d54c6973a3d30690113de93e5d9bc93a4e824b9b` identified three additional P2s:

- **P2:** canonical status/evidence still cited the earlier five-finding / CI #4023/#4024 checkpoint. This reconciliation updates the durable status set to the actual final material candidate.
- **P2:** restore/read after an ambiguous mutation did not provide an ordering barrier against an in-flight original PATCH. Final remediation changes the measured Project mutation to an authenticated/CSRF-protected idempotent write of the fixture's already-authoritative description value. A delayed or ambiguous request therefore cannot leave a benchmark marker or alternate business state behind.
- **P2:** correlation/logging middleware registered through the Nest module ran after body parsing, so malformed/over-limit parser failures were outside the observability path. Final remediation registers correlation ID and request-completion logging at the adapter layer before body parsing and adds a CI malformed-JSON regression that requires a 400 response correlation header plus matching operational log entry.
