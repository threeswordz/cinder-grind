## AC-V10-027 — Health / readiness

- `/api/v1/health/live` is dependency-free process liveness.
- `/api/v1/health/ready` checks PostgreSQL and required Documents storage.
- `/api/v1/health` remains a compatibility readiness alias.
- Production Documents readiness reuses the existing deployment-specific sentinel and verifies real write/delete availability with a bounded probe, catching capacity/quota write failures such as ENOSPC/EDQUOT.
- Health payloads remain non-sensitive.

## AC-V10-028 — Server-controlled correlation

- every request receives a server-generated UUID;
- inbound `X-Correlation-ID` is no longer authoritative;
- response/problem details retain the server correlation ID.

## AC-V10-029 — Structured operational logging

- machine-readable JSON message bodies for request completion, login outcome, startup/failure and unhandled server errors;
- migration start/complete events are emitted by the Production preparation path;
- request paths are sanitized to exclude query strings;
- credentials, tokens, request bodies, database URLs and raw storage paths are not logged.

## AC-V10-030 — Retention / rotation

`docs/OPERATIONS-RUNBOOK.md` defines bounded provider-neutral retention using native/open-source host/container facilities. The application does not create an unbounded log file.

## AC-V10-031 — Operations runbook

`docs/OPERATIONS-RUNBOOK.md` consolidates health/readiness interpretation, correlation/log lookup, startup/restart, deployment failure, backup/recovery references and initial incident triage without replacing the canonical V1.0-A/B procedures.

## Codex stable-candidate review remediation

First stable-candidate review on `a288dff64f1068840762eaf1ec8aeb88b4836727` found three genuine issues:

- **P1:** Nest log buffering would prevent structured runtime logs from reaching stdout/stderr. Remediation removes `bufferLogs: true` so default Nest logging is emitted immediately.
- **P1:** the benchmark used session-only read/mutation paths. Remediation now measures an actual Project-list read and reversible Project-description update with deterministic restore + post-run verification.
- **P2:** the stock regression guard pointed at Warehouse CRUD. Remediation now binds AC-V10-033 stock evidence to `procurement/purchase-order.integration.spec.ts`, which contains the actual competing stock-transfer / receipt-reversal regressions.

All three are present on remediation head `8729de04ccebe82c2a3ad12a4872f588e68a54f2`; push CI #4019 and PR CI #4020 both PASS.

The material re-review on final-evidence head `2e35ea615b84789ca35d4186c3b31a9b4005665e` identified two additional genuine issues:

- **P1:** storage readiness checked permissions/sentinel but did not prove a real write was possible under ENOSPC/EDQUOT conditions. Remediation adds a bounded UUID-named create/delete probe inside the configured storage root, with best-effort cleanup on failure.
- **P2:** benchmark latency stopped when response headers arrived. Remediation now consumes the complete response body before stopping the per-request timer.

These two are batched for one final exact-head CI + Codex re-review.
