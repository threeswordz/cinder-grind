# 1. Purpose

This document consolidates release-level acceptance conditions from the approved V0.3 requirements.

It does not silently decide unresolved commercial transaction rules. Those decisions are listed in `docs/V0.3-BUSINESS-RULES-PROPOSED.md` and must be approved or explicitly deferred before the affected stage begins.

# 3. BOQ & Budget

## AC-V03-001 — BOQ Structure
Requirements: BUD-001

Pass when authorized users can create the approved BOQ structure for a Project, organize sections and maintain stable BOQ item identities.

## AC-V03-002 — BOQ Item Commercial Fields
Requirements: BUD-002

Pass when BOQ items persist description, quantity, valid UOM, rate and server-validated/calculated amount according to the approved precision/calculation rule.

## AC-V03-003 — Original Budget
Requirements: BUD-003

Pass when the first approved budget baseline is clearly identifiable and preserved without later overwrite.

## AC-V03-004 — Revised Budget / Revision History
Requirements: BUD-004, BUD-005

Pass when approved revisions are retained historically and the current approved Revised Budget is derived according to the approved revision rule.

## AC-V03-005 — Budget Approval
Requirements: BUD-006

Pass when budget submission/approval/rejection uses the reusable Approval Matrix with backend maker-checker enforcement and audit attribution.

## AC-V03-006 — Budget Reporting Dimensions
Requirements: BUD-007, BUD-008, BUD-009

Pass when approved budget can be summarized by Project and, where allocated, by valid Project WBS and independent Cost Code.

## AC-V03-007 — Budget Ownership / Downstream Availability
Requirements: BUD-010

Pass when Procurement can reference approved budget data without duplicating or mutating BOQ/Budget ownership.

# 4. Purchase Request

## AC-V03-008 — Purchase Request Identity / Lifecycle
Requirements: PROC-001

Pass when an authorized user can create and maintain a Purchase Request with stable business identity and the approved lifecycle.

## AC-V03-009 — Purchase Request Lines
Requirements: PROC-002

Pass when a PR contains one or more valid demand lines with item/service context, quantity, UOM and approved Project/WBS/Cost Code allocation rules.

## AC-V03-010 — Purchase Request Approval
Requirements: PROC-003

Pass when PR submission, approval and rejection use the reusable Approval Matrix and approved records retain required history.

## AC-V03-011 — Required-on-Site Demand Date
Requirements: PROC-016

Pass when applicable procurement demand lines can carry a Required-on-Site date and approved Project/Activity context without changing schedule-owned Activity dates.

---

# 5. RFQ / Quotations / Supplier Selection

## AC-V03-012 — RFQ from Approved Demand
Requirements: PROC-004

Pass when an authorized user can create an RFQ with traceable approved procurement-demand source lines according to the approved source-selection rule.

## AC-V03-013 — RFQ Suppliers
Requirements: PROC-005

Pass when multiple active Suppliers can be invited to one RFQ and cross-Company supplier references are rejected.

## AC-V03-014 — Supplier Quotations
Requirements: PROC-006

Pass when supplier quotation header/line values are recorded against the correct RFQ/supplier and retain source-line traceability.

## AC-V03-015 — Quotation Comparison
Requirements: PROC-007

Pass when users can compare responding supplier quotation line/pricing information from canonical quotation data.

## AC-V03-016 — Supplier Award
Requirements: PROC-008

Pass when the selected supplier/award decision is explicitly recorded with traceability to the relevant RFQ and quotation data according to the approved award-granularity rule.

# 6. Purchase Order

## AC-V03-017 — Purchase Order Identity / Source
Requirements: PROC-009

Pass when an authorized user can create a Purchase Order with stable identity and traceable procurement source/award where applicable.

## AC-V03-018 — Purchase Order Lines / Pricing
Requirements: PROC-010

Pass when PO lines persist item/service, quantity, UOM, unit price and server-validated/calculated amount under the approved calculation rule.

## AC-V03-019 — PO Project / WBS / Cost Code Allocation
Requirements: PROC-011, PROC-012, PROC-013

Pass when:
- Project references are valid and Project-scope rules are enforced
- WBS belongs to the selected Project where supplied
- Cost Code remains an independent valid classification dimension

## AC-V03-020 — PO Approval / Cancellation
Requirements: PROC-014

Pass when PO submission, approval, rejection and cancellation behavior follows the approved lifecycle and reusable Approval Matrix.

## AC-V03-021 — PO Revision History
Requirements: PROC-015

Pass when approved PO revisions are preserved and earlier approved commercial values remain reviewable rather than overwritten.

## AC-V03-022 — Expected Delivery Date
Requirements: PROC-017

Pass when expected supplier delivery dates can be updated according to the approved rule without modifying schedule-owned Activity dates.

---

# 7. Procurement Schedule / Risk

## AC-V03-023 — Procurement Schedule
Requirements: PROC-018

Pass when users can review current procurement records with status, Required-on-Site and Expected Delivery dates from source transactions.

## AC-V03-024 — Schedule Risk Integration
Requirements: PROC-019

Pass when the backend applies the approved comparison rule to identify procurement lines whose expected delivery threatens the required need date, while Scheduling remains owner of Activity dates.

---

# 8. Documents / Reporting / Traceability

## AC-V03-025 — Procurement Documents
Requirements: DOC-007

Target when procurement records can link files through the existing secure Documents abstraction without creating a second storage system.

## AC-V03-026 — Procurement Reporting
Requirements: RPT-005

Pass when authorized users can filter/view PR, RFQ, quotation and PO status/key dates through source-derived reporting.

## AC-V03-027 — Forward / Backward Transaction Traceability
Requirements: SYS-007

Pass when supported transaction APIs/screens expose source and downstream references across the implemented V0.3 chain without denormalizing transaction ownership.

---

# 9. Cross-Cutting Integrity / Security

## AC-V03-028 — Company / Project Scope

Pass when Company isolation and Project-scope authorization apply to every Project-bound V0.3 transaction and direct API access is denied outside scope.

## AC-V03-029 — Commercial History Integrity

Pass when submitted/approved records that require history cannot be silently rewritten or physically deleted through ordinary application flows.

## AC-V03-030 — Validation and Audit

Pass when required fields, state transitions, references, arithmetic constraints and authenticated actor/action/timestamp audit records are enforced server-side.

## AC-V03-031 — Release Boundary

Pass when V0.3 creates no Inventory stock movement, Supplier Invoice, Payment, Actual Cost, multi-currency accounting or detailed tax/VAT ledger behavior.

## AC-V03-032 — Dependency / Runtime Constraint

Pass when no mandatory paid runtime/cloud/service dependency is introduced and production dependency audit remains green.
