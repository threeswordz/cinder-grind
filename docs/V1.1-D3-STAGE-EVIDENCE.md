## Codex final-candidate remediation (2026-10-18)

Final review of `2568fb35792cf0e5be0de32968b2a5bc9be99bed` identified two genuine findings. **P1:** a role/permission A→B→A transition could reuse preexisting cached Project or PR responses, including independently revoked Project membership, before a background refetch. **P2:** the active roadmap incorrectly stated no D3 CI had passed even though #4633–#4638 had passed.

The bounded P1 remediation clears only V1.1 Project-context and My Work query caches whenever the authenticated user/Company/effective-permission or Project source changes. Queries and visible Project/PR source data remain **disabled/hidden until the cache purge completes**. During a background Project source refresh, displayed Project/PR data stays withheld; the selected Project ID is retained until the refreshed authorized Project list determines whether it remains accessible (if revoked, it is reset). Project and PR refetches on remount/window focus are rendered as nonurgent loading rather than showing pre-refetch cached data. New QueryClient regression explicitly verifies historical A→B→A caches are removed, including stale Project memberships and PRs, while unrelated caches remain unaffected. No backend/session/permission engine/API change.

This does not provide instantaneous revocation notification while a user remains idle with unchanged identity/permissions; server APIs always enforce access, and full real-browser re-authentication/membership-change UAT remains separate. No V1.1-E human UAT claimed. **Final remediation complete:** exact material head `b22adc8647682eaa9964253c7b82fa128fe57e2e` push CI #4641 and PR CI #4642 SUCCESS, both original P1/P2 review threads resolved, batched exact-head Codex re-review clean with no findings, and PR #231 squash-merged `6649ce48800c00ece2c1c947a1af8d0f9741f7d0`, exact-main CI #4643 SUCCESS.
