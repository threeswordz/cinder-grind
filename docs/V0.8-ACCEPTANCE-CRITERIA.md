# V0.8 Management — Acceptance Criteria

**Status:** APPROVED BY PRODUCT / BUSINESS OWNER — ENTRY-GATE CLOSURE IN PROGRESS  
**Entry Gate Issue:** #160

## Source-of-truth / dashboard semantics

- **AC-V08-001** — Every V0.8 dashboard/report value is derived from canonical source-module data or an explicitly approved V0.8 non-authoritative presentation preference; no duplicate editable KPI ledger is introduced.
- **AC-V08-002** — Source-module records remain editable only through their owning modules; Management surfaces do not mutate source business records.
- **AC-V08-003** — Project Engineer dashboard presents today's/current work, activities in progress, planned/actual progress, upcoming work, delays, material/procurement risk and site issues from canonical sources.
- **AC-V08-004** — Project Manager dashboard presents Gantt/progress, delayed activities, critical path, lookahead, procurement risk, Cost Control position and major site issues for an authorized Project.
- **AC-V08-005** — Executive/Management dashboard provides authorized cross-Project visibility of project health, progress, schedule, procurement, inventory, cost, cash flow, profitability and major risks.
- **AC-V08-006** — Schedule dashboard reuses canonical Scheduling/Site semantics and does not implement a second scheduler or independent critical-path algorithm.
- **AC-V08-007** — Procurement dashboard reuses canonical Procurement status and PROC-019 Required-on-Site versus Expected Delivery risk semantics.
- **AC-V08-008** — Inventory dashboard reuses canonical stock balance/movement reporting and does not introduce unapproved inventory valuation.
- **AC-V08-009** — Cost dashboard consumes V0.7 Budget/Committed/Actual/Paid/Forecast/Cost-to-Complete/Variance definitions without conflating them.
- **AC-V08-010** — Finance dashboard consumes V0.6 AP/AR/Payment/Project Cash Flow semantics without redefining Paid Cost or cash flow.
- **AC-V08-011** — Revenue/profit indicators consume the approved V0.7 definitions for Original/Revised Contract, Actual/Forecast Revenue, Cash Received and Actual/Forecast Profit.
- **AC-V08-012** — Missing/non-applicable source measures are shown explicitly as unavailable/not applicable rather than synthesized.
- **AC-V08-013** — Cross-module report totals reconcile to the same canonical source values shown by source-module reports for the same filters.
- **AC-V08-014** — Management health/risk indicators are deterministic compositions of approved source signals; no hidden manual override becomes authoritative.
- **AC-V08-015** — Drilldown links identify canonical source records where the viewer has source permission; otherwise detail is sanitized or unavailable.

## Filtering / export

- **AC-V08-016** — Supported dashboards/reports can filter by authorized Company/Project and applicable date/status/domain dimensions.
- **AC-V08-017** — Project lists/selectors never expose inaccessible Projects.
- **AC-V08-018** — Initial approved export supports controlled CSV for supported tabular reports without requiring a paid reporting dependency.
- **AC-V08-019** — Export applies the same filters and authorization as the on-screen result and cannot export inaccessible rows/detail.
- **AC-V08-020** — Browser-printable dashboard/report views may be supported but do not create a separate persisted report truth.

## Authorization / security

- **AC-V08-021** — All Management reads enforce Company isolation.
- **AC-V08-022** — Project-scoped Management reads require effective database-derived Project access.
- **AC-V08-023** — Cross-Project/portfolio views require explicit management portfolio permission in addition to authenticated Company context.
- **AC-V08-024** — projects.access_all broadens Project visibility only; it does not silently grant management portfolio permission or protected source-module detail permissions.
- **AC-V08-025** — Technical SYS_ADMIN alone does not grant management business visibility to protected dashboards or source detail.
- **AC-V08-026** — Backend authorization remains authoritative even if frontend controls are bypassed.
- **AC-V08-027** — Aggregate results exclude inaccessible Projects before aggregation.
- **AC-V08-028** — Source drilldown still requires the relevant source-module permission; management permission does not automatically grant Finance/Subcontract/Cost mutation/detail authority.

## Financial / integrity / performance

- **AC-V08-029** — Database/server Decimal values remain authoritative for financial totals and ratios; frontend floating point is presentation only.
- **AC-V08-030** — V0.8 initial financial aggregation is base-currency-only; unsupported mixed/non-base data fails closed or is explicitly excluded with a visible reason.
- **AC-V08-031** — No synthetic Project/WBS/Cost Code allocation is introduced to make dashboards appear complete.
- **AC-V08-032** — Any cache introduced is non-authoritative, permission-safe, invalidatable and cannot survive source changes as durable business truth.
- **AC-V08-033** — Dashboard queries avoid N+1/per-row authorization patterns and meet the repository's normal practical local-prototype responsiveness expectations.
- **AC-V08-034** — Schema changes, if any are later approved, are forward-only and do not rewrite already-executed migrations.

## Technical / release gates

- **AC-V08-035** — No mandatory paid runtime/service or unapproved dependency is introduced; DEC-008 remains satisfied.
- **AC-V08-036** — Migration-from-zero, migration status, Prisma/schema validation, dependency audit, API/web validation and all prior-release regression remain green.
- **AC-V08-037** — Authorization-negative tests cover cross-Company, inaccessible Project, missing management permission, projects.access_all, SYS_ADMIN and protected source-detail leakage.
- **AC-V08-038** — Authenticated live HTTP acceptance covers Project, portfolio, domain-dashboard, filtering and export behavior on the exact release candidate.
- **AC-V08-039** — Required V0.8 Product / Business Owner human UAT remains a separate mandatory release-exit gate.
- **AC-V08-040** — V0.8 release exit requires explicit Product / Business Owner acceptance; technical/automated evidence cannot self-accept the release.
