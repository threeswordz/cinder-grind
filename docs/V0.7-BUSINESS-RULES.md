# V0.7 Cost Control — Business Rules and Owner Decisions

**Status:** APPROVED BY PRODUCT / BUSINESS OWNER — 2026-10-03  
**Approval evidence:** Issue #137 / DEC-024

## Inherited rules

- **BR-V07-01 — Source ownership:** Cost Control consumes canonical source-module data. No duplicate editable cost ledger or duplicate editable totals.
- **BR-V07-02 — Budget baseline:** the first approved V0.3 Budget Revision is Original Budget; the current/highest approved revision is Revised Budget.
- **BR-V07-03 — Cost-state separation:** Committed Cost, Actual Cost and Paid Cost remain separate.
- **BR-V07-04 — COST-014 recognition:** Supplier Actual Cost comes from final-approved Supplier Invoice lines; subcontract Actual Cost comes from approved non-reversed gross Certification; Goods Receipt alone is not Actual Cost. Approved Direct Cost Posting is the V0.7-owned additional Actual Cost source.
- **BR-V07-05 — Subcontract commitment:** approved agreement original value plus approved non-reversed subcontract Variation deltas forms the current commercial commitment ceiling. Work Orders allocate within that ceiling and are not added as a second commitment.
- **BR-V07-06 — Procurement revision semantics:** only the current applicable approved/non-cancelled PO revision contributes Procurement commitment; rejected/cancelled/superseded revisions remain history and are not additive.

## New approved V0.7 rules

- **BR-V07-07 — Remaining Commitment / Forecast:** use D07-01 and D07-03; Forecast must not double count Actual Cost or commitments.
- **BR-V07-08 — Paid Cost:** use D07-02 settlement semantics; V0.6 Project Cash Flow remains a separate Payment-level cash measure.
- **BR-V07-09 — Project Variations:** client/project Variations are Cost Control-owned and distinct from V0.5 subcontract Variations.
- **BR-V07-10 — Revenue and profit:** use D07-04; billing, cash received, forecast revenue, actual revenue and profit measures remain explicit.
- **BR-V07-11 — Dimensional ambiguity:** never invent proration. Use canonical WBS/Cost Code where directly supported; otherwise expose Unallocated.
- **BR-V07-12 — Direct Cost lifecycle:** Direct Cost Posting is for costs not already represented by AP/Subcontracts; it requires controlled approval and immutable/reversal history.
- **BR-V07-13 — Financial authority:** PostgreSQL/Prisma Decimal and server/database calculations are authoritative; frontend JavaScript floating point is presentation only.
- **BR-V07-14 — Security:** Company isolation, effective Project access and explicit cost.* permission are independent mandatory checks.
- **BR-V07-15 — Privilege separation:** projects.access_all broadens Project visibility only; SYS_ADMIN does not imply Cost Control business approval.
- **BR-V07-16 — Human release gate:** V0.7 human UAT and explicit Product / Business Owner release acceptance remain mandatory. DEC-023 is V0.6-only.

## Product / Business Owner decisions

| Decision | Approved choice |
| --- | --- |
| **D07-01 — Commitment semantics** | Committed Cost = current active gross PO commitments + current subcontract commercial ceilings. Work Orders allocate but do not add commitment. Remaining Commitment is derived after source-linked Actual, never by adding historical commitments. |
| **D07-02 — Paid Cost basis** | Paid Cost = final-approved, non-cancelled OUTBOUND Finance allocation amounts to Supplier Invoices or Subcontract Certifications. Unallocated outbound Payments remain Project Cash Flow/unallocated settlement, not Paid Cost. |
| **D07-03 — Forecast / ETC** | Persist forecast input as **uncommitted ETC**. Cost to Complete = Remaining Commitment + Uncommitted ETC. Forecast Cost = Actual Cost + Cost to Complete. Highest-version final-approved Forecast is current; avoid a manually authoritative is_current flag. |
| **D07-04 — Revenue / profit** | Actual Revenue = final-approved Client Invoice totals; Cash Received = approved non-cancelled INBOUND Payments; Forecast Revenue = Revised Contract Value; Actual Profit = Actual Revenue − Actual Cost; Forecast Profit = Forecast Revenue − Forecast Cost. |
| **D07-05 — Client Project Variations** | Separate from subcontract Variations; signed positive/negative values; approval required; approved rows immutable; correction by linked compensating reversal; only approved non-reversed values revise contract value. |
| **D07-06 — Dimensional ambiguity** | No synthetic proration. Use canonical WBS/Cost Code only where directly supported; otherwise report Unallocated. Parent WBS includes descendants. Revenue/profit stays Project-level where no approved source allocation exists. |
| **D07-07 — Direct Cost Posting** | Only for costs not already represented by AP/Subcontracts; Project + Cost Code required, WBS optional; maker-checker approval; approved immutable; correction through linked reversal; contributes Actual Cost but does not automatically become Paid Cost. |
| **D07-08 — Recognition dates** | Supplier Actual = invoice date after approval; Subcontract Actual = certification approval date; Direct Actual = posting date; Paid/Cash = Payment date; Actual Revenue = Client Invoice date after approval; Project Variation effect = approval date. |
| **D07-09 — Currency / precision** | V0.7 is base-currency-only. Unsupported non-base sources are rejected/excluded explicitly and never reinterpreted. Database/server Decimal is authoritative. |
| **D07-10 — Integrated read visibility** | cost.control.view permits authorized scoped aggregate Cost Control measures. Detailed source navigation still requires the relevant source-module permission; otherwise only sanitized Cost Control evidence is exposed. |
| **D07-11 — Equipment costing** | Defer automated EQP-009 Equipment Cost Allocation until a canonical equipment rate/valuation policy is approved. Authorized Direct Cost Posting may capture an equipment-related expense manually. |
