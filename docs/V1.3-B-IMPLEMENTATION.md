## 1. First increment: internal pricing/source-allocation core

[customer-boq-pricing.ts](../apps/api/src/budget/customer-boq-pricing.ts) implements the adopted C1–C5 calculations as a pure internal function. It uses the existing Prisma Decimal library with a separate80-digit context, preserves the selected approved stored amounts, retains source IDs/snapshots, supports explicit source shares/split/roll-up, and exposes unused coverage and the rate-rounding difference for authorized review. No UOM conversion, target-gross-margin method or early cost-allocation rounding is inferred.

Allocated costs can require **ten** fractional places: approved amount(20,4) × percentage(7,4) ÷100. The core preserves these places rather than truncate them to eight. Derived rates round half-up to four places; lines round half-up to two; total sums rounded lines. E5 yields0.99, with target1.00 and difference−0.01 explicitly available to the future maker UI. Numeric transport is exact decimal strings; no floating-point conversion or mutation of global Prisma Decimal settings occurs.

It rejects missing/unapproved/non-THB source metadata, source Company/Project mismatch, missing/duplicate/unknown line links, duplicate customer IDs, more than100% source coverage per version, undefined mapping rationale, unsupported method/mixed pricing inputs, invalid precision/ranges, unexplained zero rates and unexplained manual repricing when a previous rate is supplied. Missing source and an approved zero-cost source remain distinct.

**Caller contract, not delivered endpoint authorization:** the future service must load the approved immutable source, customer UOM precision and previous Draft rate from the database inside its transaction after real Company/Project/action authorization and current Company/Project THB-only new-money guards. Never accept a caller-supplied approval/currency/scope flag or previous price from HTTP as evidence. Source IDs, pricing inputs and the full returned cost data are confidential. Quantity Only and general Finance responses must not expose this calculation result. These checks do not prove persisted access control, concurrency, history or audit.

For C5, the core retains prior rate/reason as calculation metadata; the future service must require the persisted previous rate for edits and write immutable audit. This increment does not claim price-history persistence. Zero-rate lines retain source links and require an explicit reason; normal approval remains a later workflow obligation.

There are no new public routes, module activation, database/schema/migrations, grants, ledger effects, dependencies or UI in this increment. The function is currently consumed only by its registered automated tests. It is a reusable implementation foundation, not completed user-facing BOQ functionality.
