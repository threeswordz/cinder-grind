## 1. First increment: internal pricing/source-allocation core

[customer-boq-pricing.ts](../apps/api/src/budget/customer-boq-pricing.ts) implements the adopted C1–C5 calculations as a pure internal function. It uses the existing Prisma Decimal library with a separate80-digit context, preserves the selected approved stored amounts, retains source IDs/snapshots, supports explicit source shares/split/roll-up, and exposes unused coverage and the rate-rounding difference for authorized review. No UOM conversion, target-gross-margin method or early cost-allocation rounding is inferred.

Allocated costs can require **ten** fractional places: approved amount(20,4) × percentage(7,4) ÷100. The core preserves these places rather than truncate them to eight. Derived rates round half-up to four places; lines round half-up to two; total sums rounded lines. E5 yields0.99, with target1.00 and difference−0.01 explicitly available to the future maker UI. Numeric transport is exact decimal strings; no floating-point conversion or mutation of global Prisma Decimal settings occurs.

It rejects missing/unapproved/non-THB source metadata, source Company/Project mismatch, missing/duplicate/unknown line links, duplicate customer IDs, more than100% source coverage per version, undefined mapping rationale, unsupported method/mixed pricing inputs, invalid precision/ranges, unexplained zero rates and unexplained manual repricing when a previous rate is supplied. Missing source and an approved zero-cost source remain distinct.

**Caller contract, not delivered endpoint authorization:** the future service must load the approved immutable source, customer UOM precision and previous Draft rate from the database inside its transaction after real Company/Project/action authorization and current Company/Project THB-only new-money guards. Never accept a caller-supplied approval/currency/scope flag or previous price from HTTP as evidence. Source IDs, pricing inputs and the full returned cost data are confidential. Quantity Only and general Finance responses must not expose this calculation result. These checks do not prove persisted access control, concurrency, history or audit.

For C5, the core retains prior rate/reason as calculation metadata; the future service must require the persisted previous rate for edits and write immutable audit. This increment does not claim price-history persistence. Zero-rate lines retain source links and require an explicit reason; normal approval remains a later workflow obligation.

There are no new public routes, module activation, database/schema/migrations, grants, ledger effects, dependencies or UI in this increment. The function is currently consumed only by its registered automated tests. It is a reusable implementation foundation, not completed user-facing BOQ functionality.

## 3. Completed Customer persistence and internal approval increment

[Customer service](../apps/api/src/budget/customer-boq.service.ts) and its registered [database integration suite](../apps/api/src/budget/customer-boq.integration.spec.ts) implement the next bounded increment. Five new Prisma models retain independently numbered Customer versions, append-only edits/lines/source mappings and actor-scoped replay receipts. All prices/quantities use Decimal storage or exact decimal-string JSON snapshots; allocated source amounts retain ten fractional places. Stable customer line keys, copied UOM names/precision, source IDs/snapshots, inputs/results/reasons and rounding diagnostics remain reviewable. A new approved commercial revision links its predecessor rather than rewriting it.

Each service transaction derives current active Company/user roles and combined grants from persisted data, then Company/Project membership. Internal full-graph reads require existing explicit `budget.boq.view` + `budget.revision.view` and distinct `budget.customer.view`; writes additionally require the distinct customer manage/submit/approve action. Client permission/name/precision/prior-price flags are not authority. No permission catalog seed, retained grant or workflow configuration is changed. These future capability identifiers are tested with disposable persisted grants only. Quantity-only and Finance/public projections are not delivered here.

The service loads the approved immutable same-scope source and active Company UOM precision inside its transaction, reuses database new-money guards, and invokes the merged calculation core. Record identities use canonical lowercase UUIDs so case aliases cannot evade retained prior-line matching. Every edit appends a full snapshot; prior prices come from the retained edit. Submission uses a configured Company-scoped `CUSTOMER_BOQ` workflow and freezes content. Creator, submitter and version editors cannot decide that same version. Rejection, appended correction and resubmission retain prior instance/actions; approval uses existing configured step roles. Mutation/replay receipts contain only identity, edit number and state. History returns all prior approval instances only to the explicit full commercial reader.

Actor-scoped request UUID + canonical payload hash prevents changed-payload reuse. Serializable transactions, Project locks and bounded serialization retries protect version numbering and edit/submit/decision transitions; expected edit/instance checks reject stale writes; retry exhaustion returns a domain conflict. Audit, content and receipt commit or roll back together. Database triggers prohibit deletion/rewriting of versions/content/replays, freeze submitted/approved versions, prevent later child insertion into retained edits, validate source/actor/UOM scope, and defer nonempty line-total/mapping/coverage consistency until commit. The current-edit FK is deferred to permit atomic snapshot assembly. No existing migration is rewritten.

The [schema classifier](../deploy/release-candidate/schema-contract.mjs) admits only exact reviewed hashes for these five new models and eleven parent relation fields alongside the existing provenance/default contract. Required/defaulted/type-changed/partial/unrelated schema evolution and removal remain rejected.
