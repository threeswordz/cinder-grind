## Scope and requirement trace

Stage C implements the Forecast / ETC / Variance portion of COST-006/007/008/013 and RPT-009 under D07-01/03/06/08/09/10, BR-V07-01/03/07/11/13–16 and applicable AC-V07-013–015/020–024/026–043/047–050. It reuses the completed Stage-A integrated source read model and Stage-B Direct Cost Actual source.

- Persist versioned Cost Forecast headers and Cost Forecast lines owned by V0.7 Cost Control.
- Forecast input is **Uncommitted ETC** only. Users do not enter Remaining Commitment or total Cost to Complete.
- Current Forecast is derived as the highest-version final-approved Forecast for the Project; no manually authoritative `is_current` flag.
- Remaining Commitment = canonical current commitment less attributable recognized Actual for the same commitment, floored at zero.
- Cost to Complete = Remaining Commitment + Uncommitted ETC.
- Forecast Cost = Actual Cost + Cost to Complete.
- Variance = Revised Budget − Forecast Cost.
- Forecast lines support Project/WBS/Cost Code dimensional attribution only where canonical/entered attribution is valid; ambiguity remains explicit Unallocated. No synthetic proration.
- Forecast approval/history must remain deterministic under concurrent versions/actions and preserve prior approved versions as history.
- Base-currency-only and PostgreSQL/Prisma Decimal remain authoritative.

## Technical pre-flight

- Modular monolith / existing PostgreSQL + Prisma / existing React workspace; no new runtime service or mandatory paid dependency.
- Forward-only migrations for `cost_forecasts`, `cost_forecast_lines` and required lifecycle/history/replay/integrity guards; executed migrations remain unchanged.
- Reuse Company isolation, database-derived effective Project access and explicit `cost.forecast.view/manage/approve`; `projects.access_all` and SYS_ADMIN grant no implicit Forecast business authority.
- API family: `/api/v1/cost-control/forecasts` under the approved baseline; backend authorization remains mandatory.
- Draft create/edit; submit; approval/rejection under configured Approval Matrix and maker-checker. Approved Forecast versions are immutable.
- Version numbering/current selection must be deterministic and concurrency-safe. Only the highest-version final-approved Forecast is authoritative for current Uncommitted ETC.
- Server/database calculations must reuse Stage-A canonical measures and avoid double counting Actual Cost against Remaining Commitment.
- Source evidence remains read-only and permission-sanitized under D07-10.
- Any new business policy, permission, dependency, editable cost ledger, synthetic allocation or scope beyond the approved baseline requires explicit Change Control.
