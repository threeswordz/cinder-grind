## Planned implementation boundaries

### C1 — Browser/session/origin hardening
- preserve current database-backed session creation, expiry, revoke and CSRF semantics;
- preserve Secure + HttpOnly + SameSite=Lax Production cookie model;
- keep same-origin deployment preferred;
- validate explicit configured origin behavior and reject wildcard credentialed CORS;
- add security-header baseline without weakening application compatibility.

### C2 — Login abuse control and trusted client attribution
- replace restart-volatile login throttle state with a restart-effective open-source/self-hosted mechanism;
- prefer PostgreSQL-backed throttle state so protection does not depend on a paid proxy/service;
- if persistence requires schema state, use one reviewed forward-only migration containing security infrastructure only;
- never trust `X-Forwarded-For` / forwarding headers from an untrusted direct client;
- bind forwarded-client interpretation to an explicit trusted reverse-proxy boundary;
- rate limiting remains defensive and never substitutes for authentication/authorization.

### C3 — Request and upload limits
- introduce explicit Production request/body-size configuration and fail-closed validation;
- preserve the existing Document MIME, filename, path and configured file-size policy;
- remove or bound memory amplification from large multipart uploads while preserving approved file-size semantics;
- add deterministic oversize/body/file regression coverage.

### C4 — Error/log/OpenAPI hardening
- prevent passwords, session/CSRF tokens, secrets, raw storage paths and unsafe stacks from user-facing errors and Production logs;
- avoid echoing sensitive query material through problem-detail instance values;
- keep Production interactive API documentation disabled unless explicitly configured/restricted in approved scope;
- add deterministic leak-sentinel tests.

### C5 — Cross-module authorization / dependency evidence
- explicitly satisfy AC-V10-026 with deterministic regression proving **Project scope**, **explicit permissions**, **technical SYS_ADMIN separation** and **protected source-detail boundaries** remain intact across delivered modules;
- retain full V0.1–V0.8 authentication, authorization, Company/Project scope and maker-checker regression;
- retain `pnpm audit --prod --audit-level=high`;
- no new permission codes or business authorization semantics;
- no Production-destructive tests.
