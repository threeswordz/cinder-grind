## Scope implemented

Stage D implements the approved Project Variations / Revenue / Profit portion of V0.7 Cost Control.

- Cost Control-owned client/project commercial Variations remain distinct from V0.5 subcontract Variations.
- Project Variation values support signed positive and negative Decimal deltas.
- Draft/edit/submit/approve/reject follows explicit `cost.variation.*` permissions and configured maker-checker approval.
- Approved/rejected Project Variation history is immutable.
- Corrections use linked compensating reversals rather than silent edits/deletes.
- Original Contract Value remains Project-owned.
- Revised Contract Value is derived from Original Contract Value plus approved non-reversed Project Variation effects.
- Actual Revenue derives from final-approved Client Invoices.
- Cash Received derives from approved, non-cancelled INBOUND Payments.
- Forecast Revenue equals Revised Contract Value.
- Actual Profit equals Actual Revenue minus Actual Cost.
- Forecast Profit equals Forecast Revenue minus Forecast Cost.
- Revenue/profit remain Project-level when no approved canonical lower-dimensional allocation exists; no synthetic WBS/Cost Code proration was introduced.
- Base-currency-only and PostgreSQL/Prisma Decimal authority are preserved.
- Source evidence is permission-sanitized under D07-10.
