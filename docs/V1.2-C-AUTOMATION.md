`--plan` is offline and uses exclusive creation. Keep an existing plan instead of overwriting it. An empty plan can already check the missing approved Budget with an existing authorized persona. All omitted record/boundary checks remain BLOCKED. No extra grants are needed to report missing access.

Optionally edit the plan with `open -e "$HOME/.construction-erp-uat/evidence/v12-c-readback/plan.json"`. Add only **existing owner-identified** IDs and original recorded expected values. Do not invent a foreign Project UUID: a nonexistent ID cannot prove Company isolation. No fixture is automatically created.

Each `records` entry uses `{kind,id,projectId,expected}`. `expected` contains exact API scalar fields, using dotted field/index paths. Decimal values are JSON **strings**, with the exact original API representation (no rounding/conversion). Supported kinds and minimum expected fields:

| Kind | Required expected fields |
|---|---|
| `workOrder` | `approvalState: "APPROVED"`, `agreement.currencyCode: "THB"`, `amount` |
| `claim` | `state: "ASSESSED"`, `currencyCode: "THB"`, `assessment.state: "ASSESSED"`, `assessment.assessedAmount` |
| `certification` | `state: "APPROVED"`, `currencyCode: "THB"`, `certifiedGross`, `retainedAmount`, `netCertifiedAmount` |
| `variation` | `state: "APPROVED"`, `currencyCode: "THB"`, `valueDelta` |
| `historicalPo` / `historicalBudget` | Original `currencyCode: "SGD"` or `null`, and at least one original `lines.0.amount` (use the actual line index) |

Successor records also require retained checker/assessor identity distinct from the submitter. This passive observation is narrower than the existing CI's active denial tests. Certification readback compares retained gross/withheld/net fields; it does not certify the current Finance retention ledger or payment state. Local scripts neither approve as Ben nor attest human Ben acceptance.

Each optional `boundaries` entry uses `{kind,projectId,fixtureEvidence}`. `kind` is `foreignCompany` (expect HTTP404/PROJECT_NOT_FOUND) or `unassignedProject` (expect HTTP403/PROJECT_ACCESS_DENIED). `fixtureEvidence` identifies prior owner-verified existence/ownership evidence. The helper cannot independently establish foreign fixture existence from a denial; its receipt is conditional on that supplied evidence. An actor with `projects.access_all` cannot prove unassigned-Project denial.

Email/password are prompted; the password is hidden and neither is saved in receipts. Use existing business test personas. SYS_ADMIN is refused. The helper permits only fixed loopback `127.0.0.1:3001/api/v1` GET routes and login/logout POSTs, rejects redirects, limits requests to 15 seconds, and does not read `.env`, connect to PostgreSQL, change grants/workflows or mutate business records. Local evidence files are mode 0600 and first created exclusively. Interrupted checks leave an INCOMPLETE receipt; keep it and use a new filename for another passive readback. Credentials/cookies/raw responses are excluded from evidence. Local tracked checkout pinning is checked; the API does not attest a server SHA, so the receipt explicitly does not certify the running binary version.

Exit codes: **0 PASS** for all planned categories; **2 BLOCKED** for missing fixture/permission; **1 FAIL/error** for mismatched data, unsafe configuration or unavailable session. An observed approved Budget in this specifically missing-baseline plan is a mismatch: do not delete/change it to obtain PASS. Keep the observation and review the applicable scenario instead. Verification never upgrades BLOCKED to PASS merely because an earlier receipt was also BLOCKED.
