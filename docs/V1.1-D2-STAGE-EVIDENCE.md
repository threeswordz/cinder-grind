## Inspected defects and bounded changes

- Existing `RoleWorkspaceShell` had no scoped language metadata for Thai and Traditional Chinese V1.1 chrome. Translated navigation/group headings, menu actions, Home/My Work prompts, breadcrumbs and status messages now receive `lang` metadata **on translated labels only**. Raw employee display names, Project/PR identifiers, role codes, Company IDs and English product name never inherit a foreign language from a broad ancestor; legacy source panels retain their own language behavior. Codex P2 review of the first D2 head identified this issue and it was corrected before merge.
- Narrow screens and overlong Thai/Chinese labels, Project descriptions, role codes and workspace names risk unbroken overflow. Navigation/group/shortcut text allows wrapping, responsive Home cards allow narrow viewports, mobile Drawer width is capped to viewport width; original data is not truncated or mutated.
- My Work previously displayed "select an authorized project" when the backend-derived Project context was **loading or failed**. Queue feedback now defers to the source Project control during those states; authenticated Company/Project backend APIs remain authoritative.
- My Work records loading uses nonurgent `role=status` and `aria-live=polite`; empty/no-access states use `role=status` rather than urgent alerts. Existing error severity and source ownership remain unchanged.
