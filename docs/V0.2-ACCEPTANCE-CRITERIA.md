# 1. Purpose

This document consolidates the acceptance conditions already approved for V0.2 requirements in `docs/REQUIREMENTS.md`.

It does not add or reinterpret business rules. If implementation needs a rule not supported by the approved requirements, that rule must be surfaced through Change Control rather than silently invented.

---

# 2. Requirement Coverage

V0.2 contains:

- **47 approved requirements**
- **37 Must Have**
- **10 Should Have**

All V0.2 Must Have requirements are release-blocking under the approved Development Roadmap.

---

# 3. Acceptance Status

Each criterion is tracked as:

- Not Tested
- Pass
- Fail
- Accepted Exception

Any exception must be documented and authorized. Severity 1 defects cannot be accepted for release.

---

# 4. Scheduling Data Model

## AC-V02-001 — Activity Register and Project/WBS Context

Requirements: SCH-001, SCH-002

Pass when:

- Activities are the canonical scheduled-work entity
- authorized users can create, view and update Activities
- Activity records use valid Project/WBS context
- activity code, description, status, owner and responsible Project Engineer persist and display correctly

## AC-V02-002 — Activity Hierarchy / Summary Activities

Requirement: SCH-003

Target when:

- summary/grouping Activities can group detailed Activities
- WBS association remains intact

## AC-V02-003 — Working Calendars

Requirements: SCH-011, ADM-009

Pass when:

- working calendars support working weekdays, non-working days, working hours and holidays
- authorized administrators can configure default working/non-working rules
- Activity date calculations follow the assigned Project calendar

## AC-V02-004 — Activity Types and Responsibilities

Requirements: SCH-002, ADM-008

Pass when:

- approved Activity identification/responsibility fields persist
- configured Activity Types can be maintained and used where required

## AC-V02-005 — Dependencies and Lag

Requirements: SCH-008, SCH-009

Pass when:

- valid predecessor/successor links support Finish-to-Start, Start-to-Start, Finish-to-Finish and Start-to-Finish
- dependency lag can be represented where used
- schedule calculations preserve configured lag

## AC-V02-006 — Milestones

Requirement: SCH-010

Pass when milestones can be created, dated and displayed distinctly in schedule views.

---

# 5. Scheduling Engine

## AC-V02-007 — Planned Schedule

Requirement: SCH-004

Pass when planned duration, planned start and planned finish are stored and interpreted using the assigned working calendar.

## AC-V02-008 — Forecast Schedule

Requirement: SCH-006

Pass when forecast start/finish can differ from planned and actual dates and are available for reporting.

## AC-V02-009 — Dependency Validation

Supports: SCH-008, SCH-009

Pass when invalid dependency relationships are rejected and circular dependency prevention is covered by automated tests.

## AC-V02-010 — Critical Path

Requirement: SCH-015

Pass when Critical Path is calculated by backend/domain scheduling logic without relying on Frappe Gantt as the source of truth.

## AC-V02-011 — Total Float

Requirement: SCH-016

Pass when Total Float can be calculated for eligible Activities and is available to reporting.

## AC-V02-012 — Schedule Ownership Independence

Requirements: SCH-020, ARCH-010

Pass when replacing the Gantt visualization does not require redesigning core schedule entities or calculations.

# 6. Baseline / Progress / Delay

## AC-V02-013 — Actual Dates

Requirements: SCH-005, PRJ-008

Pass when:

- Activity actual start/finish can be captured independently from planned/baseline dates
- Project actual dates can be recorded independently of Project planned dates

## AC-V02-014 — Activity Progress

Requirement: SCH-007

Pass when percentage complete can be recorded within its allowed range and appears in schedule views.

## AC-V02-015 — Baseline Schedule

Requirement: SCH-012

Pass when baseline dates can be captured separately from current forecast and remain unchanged unless an authorized rebaseline occurs.

## AC-V02-016 — Baseline Comparison

Requirement: SCH-013

Pass when users can compare baseline dates with current/forecast dates and see schedule variance.

## AC-V02-017 — Delay Tracking

Requirement: SCH-014

Pass when delayed Activities can be identified from approved schedule data/rules and included in reporting.

# 7. Gantt / Lookahead

## AC-V02-018 — Interactive Gantt

## AC-V02-019 — Lookahead

Requirement: SCH-018

# 11. Ground Floor Slab Reference Programme

## AC-V02-033 — Groundworks Programme

Requirement: SCH-019

Pass when a 20-working-day Ground Floor Slab Groundworks programme can represent:

- Setting Out
- Excavation
- Compaction
- Blinding
- Formwork
- Reinforcement
- Inspection
- Concrete Pour

and show the required plan, actual, forecast and delay information.

The V0.2-G roadmap gate additionally requires backend schedule calculations and Gantt presentation to agree with independently tested backend results.

# 12. Cross-Cutting Release Gates

V0.2 also passes only when:

- backend authorization and Project-scope enforcement remain effective
- company isolation remains effective
- direct API authorization is tested independently of frontend visibility
- WBS and Cost Code remain independent dimensions
- `Activity` remains the canonical technical/database/API term
- audit attribution remains based on authenticated actors
- validation and safe error handling remain effective
- document access remains authorized and server paths remain undisclosed
- all source-controlled migrations apply cleanly to PostgreSQL
- automated critical/regression/security tests pass
- production dependency audit passes
- no mandatory paid runtime/cloud/service dependency is introduced
- DEC-008 remains satisfied

- Severity 1 defects = 0
- unresolved Severity 2 defects are resolved or formally accepted
- Staging/UAT validation passes
- deployment/rollback documentation is current
- Product / Business Owner explicitly accepts V0.2
