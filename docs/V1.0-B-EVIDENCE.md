## Initial DEC-022 review findings

Codex reviewed exact head `1cdeb4b6c5ec07470002eb1cb0e402abc49f41db` and identified three genuine findings:

1. **P1 — same database under another Prisma schema:** restore isolation included the Prisma `schema` query parameter even though `pg_restore` operates on the database after that parameter is removed.
2. **P1 — whole-file backup hashing:** `manifest.mjs` used `readFileSync` for recovery artifacts, which could exhaust Node memory/buffer limits as backups grow.
3. **P2 — textual recovery path containment:** repository/Documents containment checks could be bypassed by path aliases such as `..` or symlinks.

## DEC-022 remediation

All three findings were fixed without weakening the fail-closed recovery model:

- `postgres-identity.mjs` now defines database identity using hostname + port + database name, ignoring Prisma schema; `restore-drill.sh` rejects any target matching the source database identity.
- `manifest.mjs` now hashes `database.dump` and `documents.tar.gz` using `createReadStream` and incremental SHA-256.
- `path-safety.mjs` canonicalizes existing path ancestors with `realpath`, preserves missing suffixes, and performs boundary-aware repository/Documents containment checks.
- `ci-safety-regressions.sh` explicitly proves rejection of same-database/different-schema restore targets, `..` repository aliases, and symlinked recovery roots inside Documents storage.

## Fifth DEC-022 review findings and remediation

Codex reviewed documentation-reconciled candidate `cef3c697f6f69f5cfe155086f33006b3be7b3243` and identified four additional genuine recovery-safety findings:

1. **P1 — restored Documents runtime ownership:** a restore performed by root/operator could leave restored files owned by the wrong account even though operator-side verification passed.
2. **P2 — unsafe TAR member detection short-circuit:** `grep -q` combined with `pipefail` could allow an early unsafe archive member to be missed when `tar` received SIGPIPE.
3. **P2 — symlink-backed Documents:** document verification could follow a symlink and validate bytes outside the canonical storage root while the archive preserved the symlink rather than required document bytes.
4. **P2 — PostgreSQL large-object emptiness coverage:** the database-wide restore-target emptiness gate did not include `pg_largeobject_metadata`.

Fifth remediation code head `59a901d6e524ba810b4c6294c1a9a3b4678a3a47` fixes all four without expanding approved V1.0-B scope:

- restore requires explicit runtime UID/GID, uses `tar --no-same-owner`, assigns runtime ownership when executed as root, and fails closed on ownership mismatch;
- archive safety consumes the complete TAR listing before evaluating unsafe paths, eliminating the `grep -q` / `pipefail` SIGPIPE bypass;
- document verification uses `lstat()` plus canonical realpath containment; recovery creation/archive verification reject symbolic links and multiply-linked/hard-link entries;
- the database-wide emptiness query includes PostgreSQL large objects;
- focused regressions cover runtime ownership, a 2,500-entry early-`../` archive, external document symlinks and a restore target containing only a PostgreSQL large object.
