## CI failure remediation retained as regression protection

1. Earlier CI used a database polluted by negative/integration fixtures that intentionally created Document metadata without matching filesystem bytes. The recovery drill now resets only the disposable CI database/storage **after** the full regression suite passes, reapplies migrations, bootstraps the CI administrator and reruns live acceptance against a coherent database + Documents pair. Production recovery integrity checks were not weakened.
2. CI storage reset initially removed tracked `storage/.gitkeep`, causing the rollback clean-tree guard to reject the checkout. The reset now recreates the tracked empty file; the clean-tree rollback guard remains unchanged.
3. Re-running the entire mutating UAT suite after restore caused deterministic duplicate-configuration conflicts. Restored-runtime validation is now intentionally non-mutating: authenticate the existing restored administrator and verify restored runtime/database availability, while the dedicated document verifier continues to enforce all restored file metadata/size/checksum consistency.
