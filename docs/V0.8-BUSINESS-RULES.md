# V0.8 Management — Business Rules and Owner Decisions

**Status:** APPROVED BY PRODUCT / BUSINESS OWNER — ENTRY-GATE CLOSURE IN PROGRESS  
**Entry Gate Issue:** #160

## Approved business rules

- **BR-V08-01 — Source ownership:** Management composes canonical source-module data; it does not own duplicate editable operational, commercial, finance or cost totals.
- **BR-V08-02 — Read-only management layer:** V0.8 dashboards/reports are read-only decision-support surfaces. Source mutation stays in the owning module.
- **BR-V08-03 — Project health:** Management health/risk is derived from approved source signals and never becomes a hidden manually authoritative status.
- **BR-V08-04 — Schedule semantics:** Gantt, progress, baseline/current dates, delay, critical path and lookahead use Scheduling/Site semantics already implemented.
- **BR-V08-05 — Procurement risk:** material/procurement schedule risk uses PROC-019 Required-on-Site versus Expected Delivery semantics.
- **BR-V08-06 — Cost semantics:** V0.7 Budget, Committed, Actual, Paid, Forecast, Cost-to-Complete and Variance remain distinct and authoritative.
- **BR-V08-07 — Finance semantics:** V0.6 AP/AR, Payments and Project Cash Flow remain authoritative; Cash Flow is not relabeled as Paid Cost.
- **BR-V08-08 — Revenue/profit semantics:** V0.7 approved contract/revenue/cash/profit definitions are reused exactly.
- **BR-V08-09 — Missing data:** missing/unsupported data is shown explicitly as unavailable/unallocated/not applicable; V0.8 never invents a value to fill a dashboard.
- **BR-V08-10 — Security:** Company isolation, effective Project access and explicit Management permission are independent mandatory checks.
- **BR-V08-11 — Privilege separation:** projects.access_all expands Project visibility only; SYS_ADMIN does not imply Management business permission or protected source detail.
- **BR-V08-12 — Drilldown:** aggregate Management visibility does not automatically grant source-module detail; protected drilldown follows source permissions.
- **BR-V08-13 — Precision/currency:** server/database Decimal is authoritative; initial V0.8 is base-currency-only and does not introduce FX.
- **BR-V08-14 — Export:** export is an authorized representation of the same read model/filter, not a separate report source of truth.
- **BR-V08-15 — Cache discipline:** cache may improve read performance only if non-authoritative, permission-safe and invalidatable.
- **BR-V08-16 — Human release gate:** V0.8 requires Product / Business Owner human UAT and explicit release acceptance.

## Approved Product / Business Owner decisions

| Decision | Proposed choice |
| --- | --- |
| **D08-01 — Management source of truth** | V0.8 uses derived read models over canonical modules. No persistent editable KPI/management ledger. |
| **D08-02 — Dashboard freshness** | Default to current derived data. Non-authoritative server cache is allowed only for performance with safe invalidation; no durable daily snapshot warehouse in initial V0.8. |
| **D08-03 — Project vs portfolio access** | Project dashboards require effective Project access + management dashboard permission. Portfolio/cross-Project views require a separate explicit portfolio permission and include only Projects the user is entitled to see. |
| **D08-04 — Protected source drilldown** | Management aggregate visibility does not grant source detail. Drilldown requires the owning module's view permission; otherwise show sanitized evidence only. |
| **D08-05 — Project health** | Health/risk indicators are deterministic derived signals from schedule, procurement, site, cost and finance sources. No manually authoritative overall-health override in initial V0.8. |
| **D08-06 — Schedule management semantics** | Reuse existing Scheduling/Site baseline, forecast, progress, delay, critical-path and lookahead logic. V0.8 does not create a second schedule engine. |
| **D08-07 — Procurement risk semantics** | Reuse PROC-019 Required-on-Site versus Expected Delivery risk and existing procurement statuses; no second risk scoring engine. |
| **D08-08 — Cost / Finance / Profit semantics** | Consume V0.6/V0.7 approved measures exactly. Budget/Committed/Actual/Paid/Forecast/Cash/Revenue/Profit remain distinct. |
| **D08-09 — Currency / precision** | Initial Management financial consolidation is Company base-currency-only. Unsupported mixed/non-base data fails closed or is explicitly excluded; no FX conversion. Database/server Decimal remains authoritative. |
| **D08-10 — Export baseline** | Support controlled CSV export for appropriate tabular reports and browser-printable views. Defer advanced PDF/XLSX designer and scheduled distribution unless Change Control approves them. |
| **D08-11 — Analytics scope** | Initial analytics are descriptive/diagnostic status, variance and risk views from existing data. Predictive/ML forecasting and AI recommendations are deferred. |
| **D08-12 — History / warehousing** | Use existing canonical transaction/version history for drilldown and current management views. Defer a dedicated data warehouse, OLAP cube and persistent daily KPI snapshot model. |
