# 1. Purpose

This document freezes the proposed release-level scope for V0.3 Procurement using only requirements already marked **Approved** in `docs/REQUIREMENTS.md` and the approved sequence in `docs/DEVELOPMENT-ROADMAP.md`.

No new business rule becomes authoritative through this draft. Ambiguous transaction/lifecycle rules are surfaced separately for Product / Business Owner approval before implementation.

---

# 2. Release Objective

V0.3 establishes the first controlled commercial/procurement flow on top of the accepted Project/WBS/Cost Code, Material/Supplier master data and V0.2 schedule-date foundations.

The intended source flow is:

**Project / WBS / Cost Code → BOQ & Budget → Purchase Request → RFQ → Supplier Quotation → Supplier Selection → Purchase Order → Procurement Schedule Risk**

V0.3 preserves ownership boundaries:
- BOQ & Budget owns approved commercial baseline data.
- Procurement owns PR/RFQ/quotation/award/PO transactions.
- Scheduling owns Activity dates.
- Inventory owns physical stock movements from V0.4.
- Finance owns invoices/payments from V0.6.
- Cost Control owns committed/actual/paid cost measures from V0.7.

# 6. Architecture and Governance Constraints

V0.3 preserves:

- modular monolith
- PostgreSQL + Prisma
- REST API
- backend-enforced permissions
- database-derived Project scope
- reusable Approval Matrix
- immutable/auditable approved-history patterns
- WBS and Cost Code as independent dimensions
- secure Documents abstraction
- V0.2 Scheduling as owner of Activity dates
- DEC-008 open-source / zero-cost-first runtime constraint
- no mandatory paid runtime/cloud/service dependency

---

# 7. Explicit Release Boundary

V0.3 does **not** implement:

- Goods Receipt or stock posting
- Warehouse / stock ledger / stock balance
- Supplier Invoice / Accounts Payable
- Payments or Payment Allocations
- Actual Cost recognition
- Cost-to-Complete / Cost Forecast
- V0.7 committed-cost reporting/ledger
- detailed tax/VAT logic
- multi-currency accounting
- Subcontract transactions
- automatic modification of Activity schedule dates from procurement dates

PROC-020 Procure-to-Pay Traceability remains targeted to V0.6 Finance.

PROC-021 Committed Cost Feed remains targeted to V0.7 Cost Control. V0.3 may preserve the approved PO source data needed by later Cost Control, but must not redefine an approved PO as Actual Cost.

# 8. Entry Gate

V0.3 implementation may begin only when:

- V0.2 Project & Scheduling is stable and accepted
- this V0.3 Scope Baseline is explicitly approved
- the V0.3 Acceptance Criteria Baseline is explicitly approved
- blocking business rules in `docs/V0.3-BUSINESS-RULES-PROPOSED.md` are approved or explicitly deferred
- the existing approved requirements remain the source of truth
- dependency/license rules remain satisfied
- database/API baseline decisions are documented
- the V0.3 test/UAT approach is defined

---

# 9. Exit Boundary

V0.3 is not complete until:

- all V0.3 Must Have requirements meet the approved acceptance baseline
- applicable Should Have delivery/deferral status is documented
- migrations and backend/API implementation are complete
- applicable frontend workflows are complete
- permissions, Project scope, validation, maker-checker and audit controls pass
- approved commercial history/revision immutability rules pass
- transaction source/downstream traceability passes
- regression/security tests pass
- Severity 1 defects = 0
- unresolved Severity 2 defects are resolved or formally accepted with a safe workaround
- deployment/rollback documentation is current
- Product / Business Owner explicitly accepts V0.3
