# V0.8 Management — Data / API / Security / Test Baseline

**Status:** APPROVED BY PRODUCT / BUSINESS OWNER — ENTRY-GATE CLOSURE IN PROGRESS  
**Entry Gate Issue:** #160

## 1. Data baseline

V0.8 should initially add **no new canonical operational or financial business table**.

Primary data is derived from existing canonical models:

- Project / WBS / Activity / Schedule / Daily Site Report;
- Procurement and ROS-versus-Expected-Delivery risk;
- Inventory stock/movement;
- Subcontract reporting;
- Finance AP/AR/Payment/Project Cash Flow;
- Cost Control Budget/Committed/Actual/Paid/Forecast/Variance and revenue/profit.

No editable management KPI ledger, duplicate Project financial balance table, duplicate schedule state or duplicate source transaction table is permitted.

Optional user presentation preferences are not required for initial V0.8 and may be deferred unless explicitly approved.

## 2. Read-model baseline

Proposed compositional read models:

- **Project Engineer dashboard:** Project execution + schedule/site/procurement risk.
- **Project Manager dashboard:** Project execution + schedule + procurement + cost + major site issues.
- **Executive/portfolio dashboard:** authorized Project summaries across Projects.
- **Schedule dashboard:** scheduling/site indicators.
- **Procurement dashboard:** procurement pipeline and schedule-risk indicators.
- **Inventory dashboard:** balance/movement indicators.
- **Cost dashboard:** V0.7 Cost Control measures.
- **Finance dashboard:** V0.6 finance/cash-flow indicators.
- **Cross-module report:** common Project/date/status filters with source traceability.

## 3. API proposal

Approved candidate REST surfaces, subject to implementation refinement without changing approved semantics:

- `GET /api/v1/projects/{projectId}/management-dashboard`
- `GET /api/v1/management/portfolio`
- `GET /api/v1/projects/{projectId}/management/schedule`
- `GET /api/v1/projects/{projectId}/management/procurement`
- `GET /api/v1/projects/{projectId}/management/inventory`
- `GET /api/v1/projects/{projectId}/management/cost`
- `GET /api/v1/projects/{projectId}/management/finance`
- `GET /api/v1/management/reports`
- `GET /api/v1/management/reports/export.csv`

Reuse existing source/report services where practical instead of duplicating calculations.

## 4. Approved permission baseline

Approved new permissions:

- `management.dashboard.view` — Project-scoped management dashboards.
- `management.portfolio.view` — authorized cross-Project/portfolio management view.
- `management.report.export` — export an already-authorized Management report result.

Source-module permissions remain required for protected source drilldown.

No implicit grant to SYS_ADMIN is proposed. `projects.access_all` does not imply Management permissions.

## 5. Security baseline

- Company isolation applies before all Management aggregation.
- Project-scoped reads require effective database-derived Project access.
- Portfolio aggregation includes only Projects allowed by the approved D08-03 semantics.
- Protected Finance/Subcontract/Cost/source details remain permission-gated.
- Backend independently enforces all access; frontend hiding is never sufficient.
- Export uses the exact same authorization and filter boundaries as the source read model.
- Cache keys, if introduced, must include security scope and must never cross users/Companies/authorization sets.

## 6. Financial / precision baseline

- Server/database Decimal values remain authoritative.
- Reuse V0.6/V0.7 measure services/definitions where possible.
- Do not recompute financial measures using frontend JavaScript Number.
- Initial V0.8 is base-currency-only under D08-09.
- No synthetic allocation to fill missing WBS/Cost Code dimensions.

## 7. Filtering / export baseline

Minimum proposed filters where applicable:

- Company context;
- Project / authorized portfolio;
- date/from/to;
- status;
- WBS / Cost Code when canonically supported;
- source/domain-specific filters already supported by owning reports.

Initial export: controlled CSV from the server-authorized result set. No mandatory paid reporting library.

## 8. Test baseline

Minimum release coverage:

1. Project Engineer dashboard reconciliation to canonical source data.
2. Project Manager dashboard reconciliation for Gantt/progress/delay/critical path/lookahead/procurement risk/cost/site issues.
3. Portfolio aggregation across multiple authorized Projects.
4. Inaccessible Project exclusion before aggregate calculation.
5. projects.access_all without management permission denied.
6. technical SYS_ADMIN without management permission denied.
7. source drilldown sanitation without source permission.
8. schedule/procurement semantics match source modules.
9. V0.7 Cost and V0.6 Finance measure reconciliation.
10. base-currency/mixed-currency fail-closed behavior.
11. filter boundary tests.
12. CSV export row/filter/authorization parity.
13. cache isolation/invalidation tests if cache is introduced.
14. full prior-release regression.
15. authenticated live HTTP V0.8 acceptance.

## 9. Dependency baseline

Prefer existing React/TypeScript/NestJS/Prisma/PostgreSQL stack and existing open-source chart/table capabilities where sufficient.

Any new visualization/export dependency must:

- be open-source compatible;
- introduce no mandatory paid runtime/service;
- pass dependency/license review;
- be justified against existing capabilities.
