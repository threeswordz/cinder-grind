## 1. Objective and approved high-level source

Deliver controlled Subcontractor, agreement, Work Order, claim, assessment, certification, retention withholding, variation and reporting workflows under SUB-001–SUB-010 and RPT-007. This approved implementation scope interprets the high-level Requirements and roadmap; changes require recorded Change Control.

| Requirement | Approved V0.5 deliverable |
| --- | --- |
| SUB-001 | Company-owned Subcontracts register, distinct source of truth with optional same-Company Supplier link. |
| SUB-002 / SUB-004 / SUB-010 | Project-linked agreement, immutable original value/Scope of Work, configurable operational status and approval history; administrative revisions preserve history while commercial changes use approved Variations. |
| SUB-003 | Agreement-linked Work Orders with scope, amount and optional Project WBS and independent Cost Code context. |
| SUB-005 / SUB-006 / SUB-007 | Progress Claims, separate assessed value and approved Payment Certification with immutable source history. |
| SUB-008 | Agreement-configured retention withholding on certification. Release is excluded. |
| SUB-009 | Approval-controlled Variation Orders that adjust approved agreement scope/value without overwriting original value. |
| RPT-007 | Authorized, source-derived agreement/WO commitments, claimed, assessed, certified and withheld-retention reporting. |

## 3. Architecture and data baseline

- Preserve the modular monolith, PostgreSQL/Prisma, Project → WBS → Activity hierarchy and independent WBS/Cost Code dimensions.
- Reuse Company-scoped Subcontractor register authority, Project membership scope for agreements/downstream records, configured Approval Matrix, maker-checker, audit and existing technical SYS_ADMIN separation.
- ERD Section 13 is the conceptual basis for `subcontractors`, `subcontracts`, `subcontract_work_orders`, `subcontract_claims`, `subcontract_claim_items`, `subcontract_certifications` and `subcontract_variations`. Baseline additions include an optional same-Company Supplier link, retained approval/action and revision/source references, idempotency keys where a final action can be retried, and agreed retention configuration/snapshot fields and one agreement currency code inherited by downstream records. Exact schema, uniqueness and migration design are fixed during approved stage pre-flight.
- Original agreement value and Scope of Work remain unchanged; administrative revisions cannot change commercial terms. Approved Variation history is the sole source of later commercial value/scope changes and derives the current authorized ceiling. Work Orders allocate within that ceiling and are not added a second time to the agreement's commercial commitment. The approved detailed rule is BR-V05-07.
- Report only source commercial amounts in V0.5. Do not create Finance ledger/payments, Actual Cost or Paid Cost postings. V0.7 may consume approved Subcontract commitments as a separate Committed Cost source under its own baseline.

## 4. API/UI and security baseline

A permission-aware Subcontracts workspace and REST resource families under `/api/v1/subcontracts` are the approved resource-family boundary for register, agreements, Work Orders, Claims, assessments, certifications, variations and reports. Register list/maintenance is Company-scoped for explicitly authorized users. Agreement and downstream resources require server-side Project access. Exact routes, payloads and approval actions are specified at each approved stage pre-flight. A user must have both the relevant permission and valid Company/Project access. Technical SYS_ADMIN has no implicit business approval authority.

## 5. Test and UAT baseline

- Migration-from-zero/status and production dependency/license audit, no new mandatory paid runtime or service (DEC-008).
- PostgreSQL integrity and concurrency tests for Company/Project references, approved history, unique numbering, cumulative ceilings, retention and concurrent approvals.
- API security for unauthorized Project users, cross-Company references, maker-checker, permission separation and no duplicate effects on retry.
- Decimal calculation examples, reporting totals, amendment/variation history and boundary tests for claims/certification/retention under the approved BRs.
- Clean isolated full regression and live HTTP authenticated Subcontract walkthrough using unique scenario data in persistent UAT; no destructive fixture cleanup.
- Human Product / Business Owner UAT and explicit acceptance remain the separate V0.5 Release Exit Gate.

## 6. Exclusions and dependencies

- Retention release, final-account/defects-liability rules, automated expiry or retention accounting.
- Finance invoice, payments, allocation, tax/VAT, FX conversion, accounting journal and cost recognition.
- SUB-011 Finance payment reference and DOC-009 Subcontract/Finance document targets remain in V0.6; generic Project Documents remain available under their existing approved scope.
- V0.7 Committed Cost aggregation, Actual Cost, Paid Cost, profitability and forecasts. These are separate concepts and never inferred from V0.5 certification.
- No second financial ledger, paid mandatory dependency or unapproved Supplier-master replacement. Replacing the Subcontracts-owned register would require explicit SUB-001 Requirements Change Control.
