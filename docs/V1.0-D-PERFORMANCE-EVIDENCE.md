# V1.0-D Representative Performance / Capacity Evidence

**Acceptance criterion:** AC-V10-032  
**Policy:** D10-11 — representative evidence only; no contractual SLA or concurrency commitment  
**Environment restriction:** non-Production only

## Harness

`apps/api/scripts/v1-0-d-benchmark.mjs` uses Node.js built-in `fetch` and adds no dependency.

It requires:

- `BENCHMARK_NON_PRODUCTION_CONFIRMED=YES`
- `BENCHMARK_ENVIRONMENT=<non-production label>`
- `BENCHMARK_BASE_URL=<non-production /api/v1 base>`
- `BENCHMARK_EMAIL` / `BENCHMARK_PASSWORD` for a disposable authorized test user
- optional bounded `BENCHMARK_ITERATIONS` (1–500)
- optional bounded `BENCHMARK_CONCURRENCY` (1–20)

Representative flows:

1. readiness — `GET /health/ready`;
2. representative ERP read — authenticated `GET /projects` over the live Project fixture;
3. representative ERP mutation — authenticated/CSRF-protected `PATCH /projects/:id` of the Project description, immediately restored to its original value after each measured sample and verified after the run.

The harness records count, configured concurrency, wall-clock duration, throughput, average latency, p50, p95 and max latency. Each latency sample now runs through complete response-body consumption rather than stopping at response headers.

## CI evidence path

The repository CI starts an isolated API/PostgreSQL fixture, bootstraps a CI administrator, runs authenticated live acceptance and then executes the bounded V1.0-D benchmark against that same non-Production fixture.

Stable-candidate evidence must record:

- exact implementation head;
- push CI and PR CI run numbers;
- Node/PostgreSQL environment used by CI;
- configured benchmark iterations/concurrency;
- JSON benchmark output from the successful exact-head CI log;
- limitations and any observed bottleneck.

The Project-flow evidence recorded from CI #4019/#4020 proved the representative ERP fixture and deterministic restore path, but the subsequent Codex material re-review correctly identified that those latency samples stopped at response headers. Those numbers are therefore superseded for AC-V10-032 latency evidence.

The remediated harness now stops the timer only after the complete response body has been consumed. Final body-inclusive measurements will be recorded from the next exact-head successful CI run.

The earlier CI #4015 session-only benchmark (`auth/me` + CSRF rotation) remains superseded historical evidence and does not satisfy AC-V10-032.

## Interpretation limits

- Results apply only to the tested fixture/environment.
- CI runners are shared/virtualized and are not a Production sizing guarantee.
- The Project mutation is deliberately reversible and single-threaded for deterministic cleanup; it is representative business-data evidence, not a high-volume posting benchmark.
- Production load/stress testing is outside V1.0-D.
- No result in this document creates an SLA, concurrency promise or hosting-size guarantee.
