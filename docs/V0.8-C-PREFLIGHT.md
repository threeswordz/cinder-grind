## Objective

Deliver the approved Executive / Cross-Project Management Dashboard over authorized Projects using the V0.8-A Management read-model/authorization foundation and canonical source-module semantics.

## Existing foundation

V0.8-A already provides `GET /management/portfolio` behind explicit `management.portfolio.view`. It applies effective Project scope before listing/aggregation and currently returns authorized Project metadata. The contract explicitly records Stage-C deferrals for financial portfolio aggregation and cross-Project health scoring.

Stage C extends that existing contract rather than creating a second portfolio source.

## In scope

- Executive/Management portfolio dashboard for authorized cross-Project visibility;
- Project health/progress/schedule/procurement/inventory/cost/cash/profitability/major-risk indicators from canonical sources;
- deterministic derived health/risk presentation with visible unavailable/not-applicable states;
- Company base-currency-only financial aggregation using server/Prisma Decimal authority;
- effective Project scope before aggregation;
- responsive web presentation using existing open-source dependencies;
- focused API/web regression, authorization-negative coverage and authenticated live acceptance.

## Security / source-ownership boundaries

- `management.portfolio.view` is mandatory;
- `projects.access_all` and SYS_ADMIN do not imply portfolio permission;
- only Projects allowed by effective database-derived Project scope enter aggregation;
- protected source detail remains owning-module permission gated;
- no duplicate scheduler, procurement-risk engine, cost/finance calculator or editable KPI ledger;
- no frontend financial recomputation;
- no synthetic missing-dimension allocation;
- no V0.8-D domain dashboards;
- no V0.8-E reporting/export.
