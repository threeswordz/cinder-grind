## Implemented C1 behavior

- Generic `SourceLinkTarget` routes only among existing source modules: Purchase Requests, RFQ/Quotations, Purchase Orders, Goods Receipts, Supplier Invoices and Payments.
- New source-link policy requires the **owning exact view permission** before a link is shown. Manage/approve-only permissions do not create read visibility.
- Deep-linked Project IDs are accepted only after the owning backend-authorized Project list returns that Project.
- Deep-linked record IDs are accepted only after the owning Project-scoped source list returns the same record ID for that Project; RFQ quotation child IDs are accepted only from the loaded authorized RFQ detail.
- Incoming source targets are consumed once by immutable incoming Project/record identity, only after relevant React Query lists/details finish fetching; cached stale rows cannot consume a genuinely changed target early.
- Goods Receipt source-link consumption is owned by the persistent Inventory workspace so switching Inventory tabs cannot remount the receipt panel and reopen an already-consumed linked receipt.
- Source lineage links implemented:
  - RFQ → source Purchase Request(s);
  - PO line → immutable source PR, RFQ and exact Supplier Quotation;
  - Goods Receipt → source PO;
  - Supplier Invoice line → source PO and/or Goods Receipt;
  - Payment supplier allocation → source Supplier Invoice.
- Existing source modules remain owners of all submit/approve/reject/cancel/revise/reverse/post/create actions. No source transition is inferred from a UI link.
