# V1.0-D Material-Effect Concurrency / Idempotency Evidence

**Acceptance criterion:** AC-V10-033  
**Boundary:** evidence/regression consolidation only; no business-semantic change

The normal API regression command remains the executable evidence. V1.0-D adds a release-level guard ensuring the following suites remain in that command.

| Material area | Canonical regression surface | Protected invariant |
| --- | --- | --- |
| Approval / maker-checker | `apps/api/src/approval/approval.integration.spec.ts` and Finance approval races | approval actions remain serialized; duplicate/competing decisions cannot create multiple final effects |
| Finance / payments | `apps/api/src/finance/finance.integration.spec.ts` | create/replay idempotency, action replay, settlement/decision integrity and competing approval transactions remain bounded |
| Inventory stock effects | `apps/api/src/procurement/purchase-order.integration.spec.ts` | competing stock transfers, receipt posting/reversal and canonical stock movement effects remain protected by the delivered serializable transaction / lock / unique-effect design |
| Subcontract claims | `apps/api/src/subcontracts/subcontracts-claims-concurrency.integration.spec.ts` | same-period, agreement-ceiling, work-order and claim-finalization races serialize at the approved boundaries |

## Deterministic D-stage guard

`apps/api/src/release/v1-0-operations-readiness.integration.spec.ts` asserts that the API CI regression command still includes the four material suites above. The complete suite then executes those tests against isolated PostgreSQL on every V1.0-D push/PR CI run.

This deliberately avoids creating duplicate “V1.0-D business logic.” The owning modules and their existing tests remain the source of truth.

## Stable-candidate evidence

Record the final exact-head push/PR CI run numbers in the V1.0-D completion evidence. Both must execute the full API regression command successfully before merge.

Any concurrency/idempotency defect discovered during V1.0-D is a technical defect within approved scope and must be fixed before the stage is technically complete.
