# V0.7 Cost Control — Acceptance Criteria Baseline

**Status:** APPROVED BY PRODUCT / BUSINESS OWNER — 2026-10-03  
**Entry Gate Issue:** #137

## Functional / source-of-truth

- **AC-V07-001** — Original Budget comes exclusively from the first approved V0.3 Budget Revision.
- **AC-V07-002** — Revised Budget comes exclusively from the current/highest approved V0.3 Budget Revision.
- **AC-V07-003** — Cost Control cannot edit, recreate or supersede Budget-owned values.
- **AC-V07-004** — Procurement Committed Cost uses only the current applicable approved/non-cancelled PO revision and does not add superseded revisions.
- **AC-V07-005** — Subcontract commitment uses agreement original value plus approved non-reversed subcontract Variation deltas; Work Orders do not double-count that commitment.
- **AC-V07-006** — Committed Cost, Actual Cost and Paid Cost remain independently available measures.
- **AC-V07-007** — Only final-approved Supplier Invoice line amounts contribute Supplier Actual Cost.
- **AC-V07-008** — Only approved, non-reversed Subcontract Certification certifiedGross contributes subcontract Actual Cost.
- **AC-V07-009** — Goods Receipt, Stock Transaction and Material Issue do not independently create Actual Cost.
- **AC-V07-010** — Only final-approved Direct Cost Postings contribute Direct Actual Cost.
- **AC-V07-011** — Paid Cost uses D07-02 settlement semantics and does not silently become Payment cash-flow value.
- **AC-V07-012** — Source cancellation, reversal and supersession are reflected without deleting source history.
- **AC-V07-013** — Remaining Commitment is derived without double counting recognized Actual Cost attributable to the same commitment.
- **AC-V07-014** — Cost to Complete and Forecast Cost follow D07-03.
- **AC-V07-015** — Variance is deterministically derived as Revised Budget minus Forecast Cost.
- **AC-V07-016** — Only approved non-reversed Project Variations affect Revised Contract Value.
- **AC-V07-017** — Original Contract Value remains Project-owned and is not overwritten by Cost Control.
- **AC-V07-018** — Actual Revenue, Cash Received and Forecast Revenue remain distinct measures.
- **AC-V07-019** — Forecast Profit and Actual Profit use the approved revenue/cost bases without cash/cost-state conflation.
- **AC-V07-020** — Every aggregated amount can be traced to canonical source records or V0.7-owned Direct/Forecast/Project-Variation records.

## Project / WBS / Cost Code / reporting

- **AC-V07-021** — Supported cost measures roll up by Project, WBS, Cost Code and supported combinations.
- **AC-V07-022** — Parent-WBS rollup includes eligible descendant WBS values without double counting.
- **AC-V07-023** — Missing or ambiguous WBS/Cost Code attribution is shown explicitly as Unallocated; data is not silently dropped or proportioned.
- **AC-V07-024** — Cost reports expose Budget, Committed, Actual, Paid, Forecast, Cost to Complete and Variance separately and satisfy RPT-009.
- **AC-V07-025** — Revenue/profit remain Project-level where source records lack approved lower-dimensional allocation; false WBS/Cost Code profitability is not invented.

## Authorization / security

- **AC-V07-026** — All Cost Control reads/writes enforce Company isolation.
- **AC-V07-027** — Project-specific Cost Control access requires effective database-derived Project access.
- **AC-V07-028** — Cost Control requires explicit appropriate cost.* permission in addition to Project access.
- **AC-V07-029** — projects.access_all does not silently grant cost.control.view or any Cost Control mutation/approval authority.
- **AC-V07-030** — Technical SYS_ADMIN status alone does not grant Direct Cost, Forecast or Project Variation commercial approval.
- **AC-V07-031** — Backend independently enforces Cost Control authorization even when frontend controls are bypassed.
- **AC-V07-032** — Aggregate reports cannot include Projects inaccessible to the authenticated user.
- **AC-V07-033** — Cross-module source drilldown follows D07-10 and does not leak protected Finance/Subcontract detail.

## Audit / precision / integrity

- **AC-V07-034** — Direct Cost, Forecast and Project Variation material lifecycle actions retain actor/time/action/reason/history.
- **AC-V07-035** — Approved canonical V0.7 records cannot be silently edited/deleted; corrections follow approved reversal/replacement rules.
- **AC-V07-036** — Sensitive creation/action retries are idempotent and do not create duplicate financial effects.
- **AC-V07-037** — Concurrent Forecast approvals, Direct Cost actions and Project Variation approvals cannot produce duplicate current state or duplicate financial effects.
- **AC-V07-038** — PostgreSQL/Prisma Decimal and server-side calculations are authoritative; JavaScript floating point is never authoritative financial truth.
- **AC-V07-039** — Source precision is preserved through calculation; UI formatting does not modify stored/server-calculated financial amounts.
- **AC-V07-040** — Unsupported non-base-currency sources are rejected/excluded explicitly under D07-09 rather than numerically reinterpreted.
- **AC-V07-041** — Schema changes are forward-only and include appropriate integrity and lookup indexes.

## Technical / release gates

- **AC-V07-042** — No mandatory paid runtime/service or unapproved dependency is introduced; DEC-008 remains satisfied.
- **AC-V07-043** — Migration-from-zero, migration status, schema validation, targeted PostgreSQL tests and full prior-release regression remain green.
- **AC-V07-044** — Source-of-truth tests cover Original/Revised Budget, PO/Subcontract commitments and source supersession/cancellation.
- **AC-V07-045** — Tests prove Supplier/Certification/Direct Actual recognition and Goods Receipt exclusion.
- **AC-V07-046** — Tests prove Committed/Actual/Paid separation and prevent double counting.

- **AC-V07-048** — Authorization negative tests cover cross-Company, inaccessible Project, missing cost.*, projects.access_all, SYS_ADMIN and aggregate leakage cases.
- **AC-V07-049** — Concurrency/idempotency tests cover all new material V0.7 mutations.
- **AC-V07-050** — Authenticated live HTTP V0.7 acceptance passes at the exact release candidate.
- **AC-V07-051** — Required V0.7 Product / Business Owner human UAT remains a separate mandatory release-exit gate.
- **AC-V07-052** — V0.7 release exit requires explicit Product / Business Owner acceptance; DEC-023 cannot satisfy or waive it automatically.
