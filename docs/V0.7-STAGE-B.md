## Scope implemented

Stage B implements the Direct Cost portion of COST-004/COST-013 and RPT-009 under D07-07–10, BR-V07-01/03/04/11–16 and applicable AC-V07-010/020–023/026–043/045–050.

- Cost Control-owned Direct Cost Posting only for costs not already represented by AP/Subcontracts.
- Project and Cost Code are required; WBS is optional and must belong to the same Project.
- Draft creation/editing, configured Approval Matrix submission, maker-checker approval/rejection.
- Final-approved Direct Cost contributes signed Actual Cost on posting date.
- Approved history is immutable; correction uses a linked exact signed reversal retaining source dimensions and currency.
- Direct Cost does not automatically become Paid Cost or Project Cash Flow.
- Base-currency-only and PostgreSQL/Prisma Decimal remain authoritative.

## Security and integrity

- `cost.control.view` gates the Cost Control read surface.
- `cost.direct_posting.create`, `cost.direct_posting.submit` and `cost.direct_posting.approve` gate Stage-B business actions.
- Company isolation and effective database-derived Project access remain mandatory.
- `projects.access_all` does not imply Cost Control authority.
- SYS_ADMIN receives no implicit Direct Cost business authority.
- Source-detail evidence remains redacted for aggregate-only Cost Control users.
- Stable create/action keys provide replay protection.
- Row locks / SERIALIZABLE actions and the active-reversal uniqueness constraint protect concurrent material actions.
- Database triggers enforce scope, base currency, approval binding/evidence, state transitions and retained-history rules.

## API / web workflow

Primary Stage-B mutation family:

- `/api/v1/cost-control/projects/{projectId}/direct-cost-postings`
- `/api/v1/cost-control/direct-cost-postings/{postingId}`
- submit / approve / reject / linked reversal actions under the same family.

The Cost Control web workspace is permission-aware and exposes project selection, Direct Cost drafts, approval actions, linked reversal and Cost Control measure context without moving financial authority into frontend arithmetic.
