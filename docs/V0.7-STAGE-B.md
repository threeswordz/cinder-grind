## Scope implemented

Stage B implements the approved Direct Cost portion of COST-004/COST-013 and RPT-009 under DEC-024, D07-07–10, BR-V07-01/03/04/11–16 and applicable AC-V07-010/020–023/026–043/045–050.

- Cost Control-owned Direct Cost Posting only for costs not already represented by AP/Subcontracts.
- Project and Cost Code required; optional WBS must belong to the same Project.
- Draft create/edit, Approval Matrix submission, maker-checker approve/reject and retained approval history.
- Final-approved Direct Cost contributes signed Actual Cost on posting date.
- Approved financial history is immutable; correction uses one linked exact signed reversal preserving dimensions/currency.
- Direct Cost never automatically becomes Paid Cost or Project Cash Flow.
- Company base currency only; PostgreSQL/Prisma Decimal remain authoritative.

## Security and integrity

- `cost.control.view` gates aggregate Cost Control.
- `cost.direct_posting.create/submit/approve` gate Direct Cost source/action access; aggregate-only users do not query or render the Direct Cost source register.
- Company isolation and database-derived effective Project access remain mandatory; `projects.access_all` only bypasses Project assignment filtering and grants no Cost Control approval authority.
- SYS_ADMIN receives no implicit Direct Cost business authority.
- Draft material edits are maker-only; maker-checker is enforced.
- Create/action idempotency, row locking, SERIALIZABLE material actions and active-reversal uniqueness protect replay/concurrency.
- Normal postings require active Project/dimensions; historical exact reversals remain reachable after later Project/Cost Code/WBS deactivation.
- Terminal Direct Cost approval is database-authoritative: retained actions must satisfy configured step thresholds, maker-checker, explicit `cost.direct_posting.approve`, active step-role authority and effective Project scope.
- Completed Direct Cost approval instances/actions and terminal posting evidence are immutable.
- All corrective database changes after executed migrations were added as new forward-only migrations.

## API / web workflow

Primary Stage-B family:

- `/api/v1/cost-control/projects/{projectId}/direct-cost-postings`
- `/api/v1/cost-control/direct-cost-postings/{postingId}`
- submit / approve / reject / linked reversal actions under the same family.

The web workspace provides aggregate cost context plus permission-aware Direct Cost source workflows. Archived Projects with retained Direct Cost history remain selectable for historical review/reversal, while new normal Direct Cost creation stays disabled.
