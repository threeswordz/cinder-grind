## 3. Canonical source-linked journeys — AC-V11-024

### J1 — PR to Pay

`Store Site PR → Khaimook approval → Jai RFQ/quotation/selection → Jai PO draft → Ben PO approval → Goods Receipt/source evidence → Supplier Invoice/AP → Nancy configured Payment approval`.

Evidence must prove:
- source IDs/document numbers and cross-links;
- supported rejection/return/rework path;
- maker/checker and configured approval role;
- Project/Company scope on every handoff;
- no invented GR state or stock posting behavior;
- Finance single-Project/payment/allocation invariants remain source-owned.

### J2 — Subcontract to Finance

`Agreement/Work Order → Claim → Assessment/Certification → Finance/AP → Payment/Retention`.

Evidence must prove:
- claim/assessment/certification source ownership;
- SUB-009 approved variation/order history preserved;
- certification/retention/payment lineage;
- unsupported direct payable transitions denied.

### J3 — Project / BOQ / Site to Cost / Management

`Project/Team → BOQ/Budget → Scheduling/Site progress → Project Variation/Cost Control → Management views`.

Evidence must prove:
- first-approved Original Budget immutability/revision history;
- Project membership scope;
- WBS and Cost Code remain independent;
- source-backed cost/management drilldown;
- one supported rejection/return/correction path.

## 5. Security / negative matrix

At minimum capture:
- wrong Company / unauthorized Project direct API denial;
- inaccessible source record deep-link denial;
- stale/changed Project context does not expose prior cached source data;
- role/nav hiding never substitutes for backend authorization;
- SYS_ADMIN business-approval separation;
- maker/checker / no self-approval bypass;
- archived/inactive membership behavior where applicable;
- document permission plus owning-source permission;
- no role switcher, impersonation or View-As behavior.
