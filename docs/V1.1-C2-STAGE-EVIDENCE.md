## Bounded C2 runtime behavior

C2 adds source-owned navigation only. It does not create new business actions or
move transition ownership out of the existing Subcontracts and Finance modules.

- Agreement → Claims navigation uses the existing authorized Agreement and Claim source lists.
- Claim → Agreement / Work Order navigation preserves the Claim/Assessment lifecycle and links only to existing source records.
- Certification → Finance Payment navigation uses the existing certification Finance-reference endpoint and existing Payment records.
- Finance Payment allocation → Certification navigation is available only for existing `SUBCONTRACT_CERTIFICATION` allocations.
- Payable Retention → Certification navigation links existing retention evidence back to its owning Certification.
- Incoming Project and record identities are consumed once and fail closed unless returned by the user's authorized source APIs.
- Subcontract source navigation requires the existing owning view permissions; mutation-only permissions do not grant read navigation.

## Explicit business-rule preservation

- A Claim or Assessment is never made payable by navigation.
- Payment allocation eligibility remains enforced by the existing Finance backend; C2 introduces no alternative payable path.
- Certification approval/reversal and retention withholding semantics are unchanged.
- Agreement, Work Order, Claim, Assessment, Certification, Payment and Retention transitions remain owned by their existing modules.
- Company / Project scoping, maker-checker controls and approval workflows are unchanged.
