## Data / API direction

Reuse the approved V0.8 Management contract and existing canonical module report/read services.

Approved candidate surfaces remain:

- `GET /api/v1/management/reports`
- `GET /api/v1/management/reports/export.csv`

Implementation may refine route shape without changing approved semantics.

Minimum report filtering where canonically supported:

- Company context;
- authorized Project / portfolio scope;
- date / from / to;
- status;
- WBS / Cost Code;
- source/domain-specific filters already owned by canonical modules.

CSV export must be produced from the same server-authorized result/filter boundary as the on-screen report.

## Security / integrity boundaries

- Management remains read-only.
- Company isolation and effective database-derived Project access apply before aggregation.
- `projects.access_all` expands Project visibility only; it does not imply Management/report/export permission.
- technical SYS_ADMIN does not imply Management business visibility or source detail.
- protected drilldown remains gated by owning-module permissions.
- server/database Decimal remains authoritative.
- initial V0.8 financial reporting remains Company base-currency-only.
- inaccessible Projects/rows/detail must be excluded before totals/export.
- no synthetic Project/WBS/Cost Code allocation may be introduced.
- any cache remains non-authoritative, permission-safe and invalidatable.
- DEC-008 open-source / zero-cost-first remains mandatory.
